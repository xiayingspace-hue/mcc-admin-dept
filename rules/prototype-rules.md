# 原型生成规则

## 生成顺序的硬约束

原型必须晚于接口清单生成。若对应的 `outputs/api/API-<模块>-<编号>-<端侧>.md` 不存在，先跑 `/api`，不要凭空在原型里编字段名。

## 只填内容，不做设计

- 只使用 `prototypes/_shared/proto.css`、`tokens.css`、`proto.js` 提供的类名与约定，见下表。
- 原型 HTML 里不允许出现新的十六进制颜色值、不允许写内联的字体/间距体系——需要新组件时先扩展 `_shared`，全部原型受益，而不是在单个文件里私自发明一套。
- 视觉不一致是本仓要杜绝的问题：评审时注意力要落在交互对不对，而不是"这版怎么又换风格了"。

## 页面与交互约定

| 能力 | 写法 |
|---|---|
| 多页面装进一个文件 | `<section class="p-screen" id="detail" data-title="员工详情">` |
| 点击跳转 | `<button data-goto="detail">` |
| 状态切换 | 同一个数据区块内放多个 `<div data-when="empty">`，由右下角控制台切换 |
| 弹窗/提示 | `data-open="id"` / `data-close` / `data-toast="保存成功"` |
| 交互标注 | `<span class="anno" data-note="AC-003：手机号脱敏">3</span>`，编号仅用于当前页排序，`data-note` 必须回指需求文档里的 AC 编号 |
| PC 骨架 | 左侧导航 + 顶栏 + 内容区，来自 `proto.css` 的 `.p-shell` |
| 移动骨架 | 手机边框并排展示，一屏看完整个流程，来自 `.p-phone` |

## 五态硬性要求

凡是拉数据的页面，必须提供：

| `normal` | `loading` | `empty`（两种） | `error` | `noperm` | `overflow` |
|---|---|---|---|---|---|
| 真实感假数据，不用"测试测试" | 骨架屏，不是空白 | 分「从没有过」和「筛选无果」两种文案 | 原因 + 重试按钮 | 分整页拦截和字段脱敏两种 | 超长文本/超多条目不塌陷布局 |

只画 `normal` 态的页面视为未完成，`/check` 会拦截。

## 字段一致性

原型里出现的每一个字段名、每一个状态徽章文案对应的枚举值，必须能在同编号的接口清单里找到。假数据的"形状"（字段齐全、类型正确）要符合接口清单，具体取值可以编。

## 标注与追溯

每个原型页面里出现的非平凡交互（分支跳转、权限差异、校验提示）都要挂一个 `.anno`，点开显示对应 AC 编号和一句话说明。没有 AC 支撑的交互，回需求文档补 AC，不要在原型里自由发挥。
