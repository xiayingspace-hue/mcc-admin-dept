# 已发布活动的模块配置修改 测试用例

> 除特别说明外，前置条件里的「已发布活动」指：状态为已发布，已启用Celebrations（开始展示时间在未来）、寄语墙（开始展示时间已到，留言截止时间已过）两个模块（活动模块只有这两类，CEO 致辞、历史时间轴已下线）；当前登录人是行政。「当前时间」以测试环境实际时间为准，涉及「早于 / 晚于当前时间」的用例需在造数时相对于它设定。

| 用例编号 | 关联 AC / 校验规则 | 前置条件 | 操作步骤 | 预期结果 |
|---|---|---|---|---|
| QA-activity-011-admin-001 | AC-001 | 已发布活动，行政登录 | 打开该活动详情页 | 「模块配置」区块下方出现「编辑模块配置」按钮 |
| QA-activity-011-admin-002 | AC-001 | 分别准备草稿、已驳回、审批中、已结束（含已下线）的活动 | 逐个打开详情页（草稿 / 已驳回按其入口进入详情或编辑页） | 详情页都不出现「编辑模块配置」按钮 |
| QA-activity-011-admin-003 | AC-001 | 活动列表里有已发布的活动 | 查看该行操作列 | 只有「查看详情」「下线」，没有「编辑」或「编辑模块配置」 |
| QA-activity-011-admin-004 | AC-002 | 已发布活动，行政登录 | 点「编辑模块配置」 | 页面只出现各模块的启用开关、开始展示时间、留言截止时间（寄语墙）和排序；没有标题、时间、地点、预算、简介、封面图、附件、布局模板、审批人的输入项 |
| QA-activity-011-admin-005 | AC-003 | 已发布活动，打开编辑页 | 把Celebrations的开始展示时间改为另一个未来时间，保存 | 保存成功并回到详情页；活动状态仍为「已发布」；审批进度区没有新增节点或记录；统一待办列表没有新任务 |
| QA-activity-011-admin-006 | AC-003 | 同上，保存成功后 | 在用户页面（员工端）刷新该活动页 | Celebrations按新的开始展示时间显示或隐藏 |

| QA-activity-011-admin-008 | AC-004 | 同上 | 分别在请求体里夹带 计划开始时间、地点、预算、简介、封面图、附件、布局模板、第三节点审批人 | 每一次都被整体拒绝（`field_out_of_scope`），模块配置不变 |
| QA-activity-011-admin-009 | AC-005 | 已发布活动，行政 A 打开了编辑页 | 另一位行政先把该活动下线（变为已结束），A 再点保存 | A 的保存被后端拒绝，页面提示「活动已结束，无法修改」，配置不变 |
| QA-activity-011-admin-010 | AC-005 | 活动状态为审批中 / 已驳回 / 草稿 / 已结束 | 直接调用保存模块配置的接口 | 均被拒绝（`activity_not_published`），配置不变 |
| QA-activity-011-admin-011 | AC-006 | 非行政账号（如普通员工、部门主管） | 打开已发布活动的详情页 | 没有「编辑模块配置」入口 |
| QA-activity-011-admin-012 | AC-006 | 非行政账号 | 直接调用保存模块配置的接口 | 被后端拒绝（`no_permission`），配置不变 |
| QA-activity-011-admin-013 | AC-007 | 寄语墙已启用，且已有 5 条留言 | 编辑页关闭寄语墙开关，保存 | 保存成功；用户页面不再显示寄语墙；管理端留言数据仍是 5 条，没有被删除 |
| QA-activity-011-admin-014 | AC-007 | 接上一条，寄语墙已被停用 | 再次启用寄语墙并保存 | 用户页面重新显示寄语墙，原来的 5 条留言（按各自展示状态）恢复显示 |
| QA-activity-011-admin-015 | AC-007 | Celebrations已填内容，被停用后重新启用 | 停用、保存、再启用、保存 | Celebrations 原有内容完整保留，没有被清空 |
| QA-activity-011-admin-016 | AC-008 | 寄语墙留言截止时间尚未到 | 把留言截止时间改为早于当前时间，保存 | 被阻止，字段下提示「截止时间不能早于当前时间」（后端返回 `deadline_in_past`）；配置不变 |
| QA-activity-011-admin-017 | AC-008 | 寄语墙留言截止时间已过，且未改动该字段 | 只修改另一个模块的排序，保存 | 保存成功，不因为那个已过期、未改动的截止时间报错 |
| QA-activity-011-admin-018 | AC-008 / §8 截止时间不得早于当前 | 同上 | 把截止时间改为恰好等于保存时刻 | 被阻止（不晚于当前时间视为早于），提示同上 |
| QA-activity-011-admin-019 | AC-009 | 寄语墙开始展示时间已到，用户页面正在显示 | 把它的开始展示时间改为未来时间，保存 | 被阻止，提示「该板块已在用户页面显示，不能把开始展示时间改到未来，想收回请停用」（`display_start_in_future`）；配置不变 |
| QA-activity-011-admin-020 | AC-009 | Celebrations开始展示时间在未来（尚未显示） | 把开始展示时间改到更晚的未来时间，保存 | 保存成功 |
| QA-activity-011-admin-021 | AC-009 | 寄语墙开始展示时间已到 | 把开始展示时间改到更早的过去时间，保存 | 保存成功（只限制改到未来） |
| QA-activity-011-admin-022 | AC-009 | 寄语墙开始展示时间未填（发布后即显示） | 填一个未来的开始展示时间，保存 | 被阻止（已在显示的模块不能改到未来），提示同上 |
| QA-activity-011-admin-023 | AC-010 | 已发布活动，计划开始时间已知 | 把寄语墙留言截止时间改为早于活动计划开始时间（但晚于当前时间；如当前时间早于计划开始时间则可构造） | 被阻止，提示「留言截止时间须晚于活动计划开始时间」（`validation_failed`） |
| QA-activity-011-admin-024 | AC-010 | Celebrations设有开始展示时间 | 给寄语墙同时设置：开始展示时间晚于它自己的留言截止时间，保存 | 被阻止，提示「开始展示时间不能晚于截止时间」（`validation_failed`） |
| QA-activity-011-admin-025 | AC-011 | 行政 A、B 同时打开同一活动的编辑页（看到同一配置版本） | A 修改并保存；B 随后修改另一项并保存 | A 保存成功；B 被拒绝，提示「配置已被他人修改，请刷新后重试」（`config_version_conflict`），A 的修改没有被覆盖 |
| QA-activity-011-admin-026 | AC-011 | 接上一条，B 看到冲突提示 | B 点「刷新」 | 页面显示 A 修改后的最新配置；B 重新修改并保存后成功 |
| QA-activity-011-admin-027 | AC-011 / §8 并发校验 | 直接调用保存接口 | 带一个过期的 `config_version` | 被后端拒绝（`config_version_conflict`），配置不变 |
| QA-activity-011-admin-028 | AC-012 | 已发布活动，行政修改了启用状态、开始展示时间、排序各一项 | 保存 | 生成一条修改记录，包含操作行政、保存时间，并逐项列出改动的模块与项、改前值、改后值（共 3 项） |
| QA-activity-011-admin-029 | AC-012 | 保存因校验失败被拒绝 | 查看修改记录 | 没有新增记录 |
| QA-activity-011-admin-030 | AC-012 | 保存因版本冲突被拒绝 | 查看修改记录 | 没有新增记录 |
| QA-activity-011-admin-031 | AC-012 / §8 留痕 | 模拟记录写入失败 | 提交一次合法的修改 | 本次保存整体失败（`log_write_failed`），页面提示可重试；重新打开配置，内容仍是修改前的值；修改记录没有新增 |
| QA-activity-011-admin-032 | AC-012 | 保存时没有改动任何项 | 点保存 | 提示「没有改动」，不调用保存 / 不产生记录 |

| QA-activity-011-admin-034 | AC-014 | 活动处于草稿 / 已驳回，发起人登录 | 进入创建流程步骤二修改模块配置，保存 | 行为与改动前一致：随活动整体编辑，不出现「发布后修改」的限制提示，也不产生修改记录 |
| QA-activity-011-admin-035 | AC-015 | 活动发起人是行政 A，行政 B 与 A 不是同一人 | B 登录，打开该已发布活动详情页 | B 看到「编辑模块配置」入口，修改并保存成功 |
| QA-activity-011-admin-036 | AC-015 | 同上 | B 保存成功后，A 查看修改记录 | A 能看到 B 的修改记录，操作人显示 B 的姓名 |

| QA-activity-011-admin-038 | AC-016 | 同上 | 查看「修改记录」区块 | 区块是只读的，没有编辑、删除按钮 |
