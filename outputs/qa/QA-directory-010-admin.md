# 内部人员与外部人士的录入 测试用例

| 用例编号 | 关联 AC / 校验规则 | 前置条件 | 操作步骤 | 预期结果 |
|---|---|---|---|---|
| QA-directory-010-admin-001 | AC-001 | 行政打开作品上传表单、行政代报名表单、留言代录入表单（三处各测一次） | 选"内部员工" | 姓名区域是员工选择器（不是文本输入框），所属区域是部门 / 项目选择 |
| QA-directory-010-admin-002 | AC-001 | 同上 | 选"外部人士" | 姓名为手动输入；部门 / 所属机构为自由文本输入框；没有 HR 选择器 |
| QA-directory-010-admin-003 | AC-002 | 选"内部员工"，HR 里有员工"陈思思 / E1001 / 产品部" | 在员工选择器搜"陈思" | 列表出现陈思思，显示姓名、工号、部门；选中后保留这三项信息 |
| QA-directory-010-admin-004 | AC-002 | 同上 | 搜工号"E1001" | 同样能搜到并选中 |
| QA-directory-010-admin-005 | AC-002 | 同上 | 搜一个 HR 里不存在的名字 | 提示"HR 系统中没有匹配的员工"，没有任何可添加项；不能把输入的文字直接当员工添加 |
| QA-directory-010-admin-006 | AC-003 | 已选中一位员工 | 在所属里先选一个部门，再选一个项目 | 后选的替换先选的，最终所属只有一个（项目）；不能同时存在部门和项目 |
| QA-directory-010-admin-007 | AC-003 | 同上 | 在所属里搜一个 HR 里不存在的部门 / 项目 | 提示没有匹配，不能手填，所属保持原值 |
| QA-directory-010-admin-008 | AC-003 | 已选中员工 | 清空所属后保存 | 保存成功，所属为空，展示方式沿用各模块（如名单显示"—"） |
| QA-directory-010-admin-009 | AC-004 | 单人场景（代报名 / 留言 / 单作者作品），员工属于"产品部" | 选中该员工 | 所属自动带出"产品部"；可改选别的部门或某个项目，也可清空 |
| QA-directory-010-admin-010 | AC-004 | 作品上传，作者类型内部员工 | 先后选 3 位不同部门的员工 | 所属不自动带出，保持为空；行政可自己选一个部门或项目 |
| QA-directory-010-admin-011 | AC-005 | 选"外部人士" | 部门 / 机构填"合作伙伴 · XX公司"，保存；另一次留空保存 | 两次都保存成功；展示为所填文本 / 按各模块规则展示空值 |
| QA-directory-010-admin-012 | AC-006 | 已选"内部员工"并选了员工和所属 | 切到"外部人士" | 已选的员工和所属被清空，姓名、部门 / 机构输入框为空 |
| QA-directory-010-admin-013 | AC-006 | 已选"外部人士"并手填了姓名和机构 | 切到"内部员工" | 已手填的姓名和机构被清空，显示空的员工选择器 |
| QA-directory-010-admin-014 | AC-007（后端） | 内部员工类型 | 直接调用保存接口，传一个 HR 里不存在的 `employee_id` | 被拒绝并返回明确原因，不产生记录 |
| QA-directory-010-admin-015 | AC-007（后端） | 内部员工类型 | 直接调用保存接口，只传姓名文本、不传 `employee_id` | 被拒绝，不产生记录 |
| QA-directory-010-admin-016 | AC-007（后端） | 内部员工类型 | 直接调用保存接口，传不存在的部门 ID / 项目 ID；或同时传部门和项目 | 均被拒绝，不产生记录 |
| QA-directory-010-admin-017 | AC-007（后端） | 外部人士类型 | 直接调用保存接口，带上 `employee_id` 或 HR 部门 / 项目 ID | 被拒绝，不产生记录 |
| QA-directory-010-admin-018 | AC-008 | 模拟 HR 系统超时 | 在员工选择器里搜索 | 显示错误与"重试"；没有手动输入的兜底入口 |
| QA-directory-010-admin-019 | AC-008 | 接着上一条，此前已选中了一位员工 | 点击"重试"，恢复后再搜索 | 重试后可正常搜索选择；此前已选的员工没有丢失 |
| QA-directory-010-admin-020 | AC-009 | 已有一条内部员工记录，所属选了项目"星火计划" | 查看列表 / 详情 / 名单 | 所属显示"星火计划"；外部人士的记录显示手填机构；所属为空的按各模块规则显示 |
| QA-directory-010-admin-021 | AC-010 | 改造前创建的记录，所属是自由文本"产品部" | 打开列表 / 详情 | 仍显示"产品部"，不要求补选，不报错 |
| QA-directory-010-admin-022 | §9 五态-overflow | HR 里有姓名和部门名称都很长的员工 | 选中该员工 | 文字换行或截断，不撑破表单布局；作品选了多位员工时换行展示 |
| QA-directory-010-admin-023 | AC-002 / AC-011 | HR 里有一位离职员工"吴磊 / E1011" | 在员工选择器里搜"吴磊"、搜"E1011"；直接调用 `hrEmployee` 接口带同样关键字 | 页面和接口都搜不到、不返回该员工（提示"HR 系统中没有匹配的员工"） |
| QA-directory-010-admin-024 | AC-003 / AC-011 / AC-014 | HR 部门树：集团 → 技术中心 → 后端组（末级） | 打开部门选择；直接调用 `hrDepartment` | 组件按树展示，可逐级展开；接口返回树结构，末级部门的 `children[]` 为空 |
| QA-directory-010-admin-025 | AC-003 | 已选"后端组" | 查看已选标签和保存后的列表 / 名单 | 只显示"后端组"，不带上级路径（不是"集团 / 技术中心 / 后端组"） |
| QA-directory-010-admin-026 | AC-003 / AC-011 | HR 里项目"旧项目"已关闭，"星火计划"有效 | 在项目选择里搜两者；直接调用 `hrProject` | 只能搜到、返回"星火计划"，"旧项目"不出现、不能选 |
| QA-directory-010-admin-027 | AC-007（后端） | 内部员工类型 | 直接调用保存接口，传离职员工的 `employee_id`、上级（非末级）部门 ID、已关闭项目 ID | 均被后端拒绝，不产生记录 |
| QA-directory-010-admin-028 | AC-012 | 已有一条内部员工记录：姓名"陈思思"，所属"产品部" | 在 HR 里把她改名为"陈思思（Sissy）"、调到"市场部"；再查看该记录 | 记录仍显示"陈思思""产品部"，不变 |
| QA-directory-010-admin-029 | AC-012 | 已有一条所属为项目"星火计划"的记录 | 在 HR 里关闭该项目；再查看该记录 | 记录仍显示"星火计划"，不变 |
| QA-directory-010-admin-030 | AC-013 | 已有一条记录，其员工后来已离职 | 打开编辑，不改员工和所属，只改其他内容后保存 | 保存成功，员工和所属原样保留 |
| QA-directory-010-admin-031 | AC-013 | 同上 | 编辑时移除该员工，再重新搜索选择 | 搜不到该离职员工，不能再选回；改选其他在职员工后可保存 |
| QA-directory-010-admin-032 | AC-014 | 部门选择已打开，树为 集团 → 技术中心 → 后端组 | 点击"技术中心" | 只展开 / 收起它的下级，不选中，所属不变 |
| QA-directory-010-admin-033 | AC-014 / AC-003 | 同上，已展开到"后端组" | 点击"后端组" | 选中，已选标签只显示"后端组"（不带"集团 / 技术中心"） |
| QA-directory-010-admin-034 | AC-014 | 树里有两个同名末级部门"市场部"（分别在运营支持中心下和新加坡分公司下） | 在部门选择里搜"市场" | 列出两个"市场部"，每条旁用淡色文字显示各自上级路径用于区分；选中其中一个后只显示"市场部" |
| QA-directory-010-admin-035 | AC-014 | 搜索关键字只匹配上级部门名称（如"技术中心"） | 搜"技术中心" | 不列出"技术中心"本身（它不可选）；如其下有名称匹配的末级部门才会列出 |
| QA-directory-010-admin-036 | AC-014 | 已选一个部门 | 点击已选标签上的清空 | 所属清空，可重新选择 |
| QA-directory-010-admin-037 | AC-014 / AC-008 | 模拟 HR 超时 | 打开部门选择 | 显示错误与"重试"，没有手动输入兜底；恢复后重试，部门树正常显示 |
| QA-directory-010-admin-038 | §9 五态-overflow | 部门树层级很深（5 层以上），或有名称很长的部门 | 逐级展开到最深一层 | 组件不撑破表单，可滚动；长名称换行或截断 |
