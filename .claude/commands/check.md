# /check — 全仓一致性检查

用法：`/check`

只读检查，不写文件，在终端输出报告。检查项：

1. **编号唯一性**：`requirements/versions.md` 里的编号是否唯一、是否连续（允许跳号但要在依赖树里说明原因）。
2. **命名规范**：所有文件名是否符合 `rules/global-rules.md` 的命名模式。
3. **slug 受控**：文件名里出现的模块 slug 是否都已在 `GLOSSARY.md` 登记，总数是否 ≤10。
4. **派生完整性**：每个「已确认」状态的需求，是否都有对应的 `outputs/api/`、`outputs/qa/`、`prototypes/`；缺失的列出来。
5. **字段一致性**：抽查原型里出现的字段名/枚举值，是否能在同编号接口清单里找到。
6. **五态覆盖**：原型文件里拉数据的区块，是否都有六个 `data-when` 值（含两种 empty）。
7. **标注可追溯**：原型里的 `.anno` 是否都能在需求文档里找到对应 AC 编号。
8. **空壳文件**：`<端侧>/<载体>/` 下是否存在内容与 `shared` 完全重复、没有真实差异的空壳文件。
