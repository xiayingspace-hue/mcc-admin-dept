# 跨需求统一约定

以下约定适用于全仓所有需求文档、接口清单、原型，需求文档不重复定义，直接引用本文件章节。

## 时区

`Asia/Singapore`。所有时间字段的展示与存储均以此时区为准；如后端存储 UTC，前端展示前统一转换，转换规则不在需求文档里逐个重复。

## 分页

默认每页 20 条，offset + limit 方式。列表类接口清单不重复定义分页参数，直接写"分页：见 conventions.md"。

## 金额精度

人民币元，页面展示精确到元（不显示小数），传输与存储以「分」为单位的整数，避免浮点误差。

## 时间格式

接口传输统一 ISO 8601（`2026-11-20T14:00:00+08:00`）；页面展示格式由原型自行决定，不强制统一显示格式。

## 接口路径与请求方式

管理端真实后端为 `aiis-admin` 系统，`outputs/api/` 里的路径一律按此规则写，不再逐份清单各写一套：

- **前缀**：`/mcc-api/aiis-admin/`，只写相对路径，不写域名（域名为 `https://aiis-prod.mcc.sg` 等按环境区分，不进本仓）。
- **资源段**：单数、camelCase，对应需求文档「数据对象」的实体名，例如 `activity`、`activityModule`、`moduleType`、`submission`、`registration`、`wallMessage`；不加复数 `s`。
- **HTTP 方法**：保留标准 RESTful 语义——`GET` 查询、`POST` 创建/触发业务动作、`PUT` 整体更新、`PATCH` 局部更新、`DELETE` 删除。方法已经表达了"查/增/改/删"，资源段本身不再叠加 `queryAll`/`save` 这类动作后缀。
- **业务专属动作**：没有对应标准动词的操作（提交审批、发布、隐藏、签到、审批通过/驳回等状态流转），在资源段后追加语义化动词段，如 `/activity/submit`、`/submission/publish`、`/registration/check-in`。
- **不用路径参数传 id**：URL 里不出现 `{id}`；`GET` 请求把 id 放请求体，其余方法（`POST`/`PUT`/`PATCH`/`DELETE`）把 id 作为请求体字段（如 `id`、`activity_id`、`step_id`），与其余业务字段并列传输。

## 软删除 vs 硬删除

- **草稿状态**的活动、**未发布**状态的作品/留言：允许硬删除，删除即物理移除，无需保留记录。
- **已发布**及之后状态（已发布/已结束/已驳回）的活动：不提供删除，只提供"下线"（状态转移，记录保留）。
- **已展示**过的寄语/作品被"隐藏"：软删除，记录保留、仅从对外展示中移除，因为可能涉及审核追溯。

## 状态命名统一术语

跨模块的状态命名保持一致，不同模块间不要用不同词表达同一概念：

| 术语 | 含义 | 适用对象 |
|---|---|---|
| `draft` 草稿/未发布 | 已创建，未对外生效 | 活动、作品 |
| `review` 待审核/审批中 | 已提交，等待处理 | 活动审批、寄语 |
| `published` 已发布/已展示 | 对外生效 | 活动、作品、寄语 |
| `hidden` 已隐藏 | 曾经对外生效，现临时/永久收回，记录保留 | 作品、寄语 |
| `ended` 已结束 | 活动生命周期终止 | 活动 |
| `rejected` 已驳回 | 审批未通过，退回发起人 | 活动审批 |

## 权限与可见性的两个独立维度（易混淆，专门澄清）

- **参与范围**：内部员工里，谁能报名/参与（全员 / 指定部门）。
- **外部可见性**：活动页面本身是否允许内部员工之外的人访问（仅内部可见 / 对外部人员开放）。

两者独立设置，互不隐含。模块自身的"是否允许外部人士留言/提交"等开关（属于 `module` 数据对象的一部分），逻辑上不应与活动的"外部可见性"矛盾——即活动设为"仅内部可见"时，模块级别的外部相关开关不应生效，具体校验规则见 `requirements/admin/shared/module-002-admin.md` §8。
