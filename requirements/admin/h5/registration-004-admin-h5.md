# 现场扫码签到页（registration-004-admin-h5）

> 本文档只写**载体差异**：现场工作人员在手机上（企业微信内嵌网页）用来扫码签到的这一页。签到的业务规则、权限、校验、签到时间窗口、验收标准，以 [`registration-004-admin`](../shared/registration-004-admin.md) 为准，这里不重复。

## 1. 概述

活动现场，持有签到权限的工作人员用手机打开本页，对准参与者出示的签到码二维码扫描，立即得到签到结果。本页只做扫码签到这一件事，不包含管理后台的其他功能。

**非目标**：本页不展示报名名单、不做手动签到 / 撤销签到（那些在管理端 `pc` 完成）；不提供按姓名搜索签到。

## 2. 涉及角色

引用 [`ROLES.md`](../../shared/ROLES.md)：现场签到人员（持有签到权限的账号，含行政）。

## 3. 术语与模块归属

引用 [`GLOSSARY.md`](../../shared/GLOSSARY.md)：签到码、签到时间窗口。依赖 `registration-004-admin`。

## 4. 使用场景

- 活动当天，工作人员站在入口，参与者逐个出示自己的签到码，工作人员扫码，核对屏幕上的姓名后放行。
- 参与者的手机没电或码打不开时，工作人员请其稍后再来，或由行政在管理端手动签到。

## 5. 业务流程与状态机

页面流转（每次扫码都是一次完整的小循环）：

| 当前 | 触发 | 下一步 |
|---|---|---|
| 待扫描 | 扫到一个签到码 | 验证中 → 结果页（五种之一） |
| 结果页 | 点击"继续扫码" | 待扫描 |
| 待扫描 | 摄像头无法使用（未授权 / 设备不支持） | 摄像头不可用提示，提供手动输入签到码 |

## 6. 数据对象

本页不新增数据对象，使用 `registration-004-admin` §6 的报名记录与签到码。结果页展示的字段：姓名、部门或所属机构、所属 Celebration 的 Site 名称、签到结果。不展示电话、邮箱。

## 7. 权限规则

- 无签到权限的账号打开本页，整页被拦截，提示"无签到权限"（规则见 `registration-004-admin` §7，AC-020）。
- 本页不要求账号有管理后台其他功能的访问权限。

## 8. 校验规则

- 扫码结果的判定、签到时间窗口，全部由后端按 `registration-004-admin` §8 判定；本页只负责展示结果，不在前端判断签到码是否有效或是否在窗口内。
- 摄像头不可用（用户拒绝授权、设备不支持）时，提供"手动输入签到码"的备用方式，输入后走同样的后端判定（该备用入口已与行政确认）。

## 9. 页面与状态清单

| 页面 | 需要的状态 |
|---|---|
| 扫码签到页 | normal(待扫描) / loading(验证中) / error(网络失败，可重试) / noperm(无签到权限，整页拦截) / overflow(姓名或机构很长时不撑破布局) / 摄像头不可用（提示 + 手动输入） |
| 扫码结果页 | 签到成功 / 已签到 / 无效的签到码 / 不在签到时间内（四种结果，各有独立的文案与视觉区分） |

> empty 状态不适用：本页没有列表，不存在"从未有过"或"筛选无果"。

## 10. 验收标准

- AC-H01：打开本页，持有签到权限的账号看到取景框和"将签到码对准取景框"的提示；扫到码后先显示"验证中"，再进入结果页。
- AC-H02：四种结果页文案分别为"签到成功""该参与者已签到""无效的签到码""不在签到时间内"，视觉上能一眼区分成功与失败；成功与已签到的结果页显示姓名、部门、所属 Celebration，不显示电话和邮箱。
- AC-H03：结果页点击"继续扫码"回到待扫描，可立即扫下一个。
- AC-H04：摄像头未授权或设备不支持时，显示"摄像头不可用"的提示，并提供手动输入签到码的入口；输入后得到与扫码相同的结果页。
- AC-H05：网络失败时显示错误提示与"重试"，不显示任何结果；重试后重新请求同一个签到码。
- AC-H06：姓名或机构名称很长时，结果页内文字换行或截断，不撑破布局，"继续扫码"按钮始终可见。
