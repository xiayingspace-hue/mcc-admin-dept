# 活动模块配置与模块库（module-002-admin）

## 1. 概述

活动内部的具体"玩法"以"模块"的形式挂载使用，挂载对象分两类：挂载在**活动**上的"活动模块"（CEO致辞、历史时间轴、周年博客列表、寄语墙），行政在创建活动流程第二步勾选启用并配置参数；挂载在 **Celebration**（活动下某个 site 的分站点子活动）上的"CelebrationModule"（报名信息、涂鸦展示），其专属规则由 `celebration-007-admin` 定义，本文档不重复承载。"模块库"统一收录全部六种模块类型的说明作为只读参考目录，不区分挂载对象，供行政配置前浏览参考。

**非目标**：不支持行政自定义新的模块类型；模块库不提供新增/删除模块类型的入口，新类型需要开发实现。

## 2. 涉及角色

引用 [`ROLES.md`](../../shared/ROLES.md)：仅行政操作本模块的配置与浏览。

## 3. 术语与模块归属

引用 [`GLOSSARY.md`](../../shared/GLOSSARY.md)：活动模块、CelebrationModule、模块库、开始展示时间。依赖 `activity-001-admin`（活动必须先存在才能挂载模块）。**变更说明（自 REQ-007 起）**：报名信息、涂鸦评选（现称"涂鸦展示"）两类模块类型的挂载对象、数据对象字段、状态机与校验规则已迁移至 `celebration-007-admin` 承载，本文档不再定义这两类模块的挂载规则，仅在模块库中保留其类型说明供参考；`submission-003-admin`、`registration-004-admin` 依赖 `celebration-007-admin`，不再依赖本文档。

## 4. 使用场景

- 行政创建活动时，在第二步勾选本次活动要启用的活动模块（CEO致辞/历史时间轴/周年博客列表/寄语墙），并填写每个模块的专属参数。
- 行政配置前，先去模块库浏览"历史上这个模块被哪些活动/Celebration 用过、配置成什么样"作为参考。
- 行政希望某个板块（如历史时间轴）不要一发布就出现，而是活动当天才揭晓。

## 5. 业务流程与状态机

### 5.1 模块的两层状态

**启用状态**（是否挂载）：由行政在配置步骤的开关直接控制，不需要状态机——开则创建对应的活动模块记录，关则不创建/移除。

**展示与阶段状态**（挂载后，模块自身何时可见、内部处于什么阶段）：由时间戳字段计算得出，不做成需要人工点击切换的显式状态，具体规则：

```
当前时间 < 开始展示时间           → 模块整个不渲染（对用户不可见，不是禁用态）
开始展示时间 ≤ 当前时间 < 提交截止时间   → （若模块有提交环节）提交中
提交截止时间 ≤ 当前时间 < 投票截止时间   → （若模块有投票环节）投票中
当前时间 ≥ 最后一个截止时间          → 已结束（展示最终结果，只读）
```

未配置"提交/投票/留言截止时间"的模块（如 CEO致辞、历史时间轴），只有"开始展示时间"这一层判断，没有内部阶段流转。涂鸦展示模块的内部阶段细化（作品来源为行政上传、无"员工提交"开放阶段）见 `celebration-007-admin` §5.3。

## 6. 数据对象

**活动模块（ActivityModule）**：某个活动实例启用的某一种挂载在活动上的玩法。归属某个模块类型（`module_type`：`ceo_speech`/`timeline`/`blog_list`/`wall`），带有该活动此次启用时的专属配置（如寄语墙的展示样式）、通用配置（开始展示时间、排序）、以及模块的分类属性（内容型：行政直接编辑发布的内容，如CEO致辞、历史时间轴、周年博客列表；互动型：需要收集用户交互的模块，如寄语墙）。挂载在 Celebration 上的"报名信息""涂鸦展示"两类模块，其数据对象定义见 `celebration-007-admin` §6 的 CelebrationModule。

**模块类型参考信息（模块库条目）**：每种模块类型（含挂载在活动上与挂载在 Celebration 上的全部六类）的说明、可配置属性清单、历史使用记录，由开发维护，行政只读浏览，不属于可编辑的数据对象。

## 7. 权限规则

- 仅行政可以勾选启用/停用活动模块、填写模块配置参数，操作发生在活动仍处于可编辑状态（草稿/已驳回）时；活动进入审批中及之后状态，模块配置随活动一起锁定，不可单独修改（与 `activity-001-admin` §7 的编辑限制一致）。报名信息、涂鸦展示两类模块的权限规则见 `celebration-007-admin` §7，不受活动生命周期状态限制。
- 模块库为全员行政只读，不区分更细的权限层级。

## 8. 校验规则

- 寄语墙：留言截止时间若填写，必须晚于活动计划开始时间；若不填，视为与活动同时结束。
- 所有挂载在活动上的模块，其"开始展示时间"若填写，不得晚于该模块自身的任何截止时间字段，避免出现"模块还没开始展示，提交却已经截止"的逻辑矛盾。挂载在 Celebration 上的模块不使用"开始展示时间"（由展示开关控制，见 `celebration-007-admin` §5.3），对应校验规则见 `celebration-007-admin` §8。
- **联动校验（跨模块）**：当活动的"外部可见性"（见 `activity-001-admin`）为"仅内部可见"时，寄语墙的"允许外部人士留言"开关不应为"是"；提交/保存时给出提示，具体是阻止保存还是仅警告，属已知缺口（见 §11）。

## 10. 验收标准

- AC-001：勾选启用某个活动模块后，该模块的专属配置字段区域展开显示；取消勾选后配置区域收起，且已填写的值不提交（不创建对应活动模块记录）。
- AC-002：（涂鸦展示投票/提交截止时间校验已随挂载对象变更迁移至 `celebration-007-admin` AC-006，本文档不再保留，编号不复用）
- AC-003：任一活动模块设置"开始展示时间"晚于活动本身的"开始展示时间"上限（各自的截止时间字段）时，保存时报错阻止。
- AC-004：模块库中每张模块卡片展示"可配置属性"清单和"已被 N 个活动/Celebration 使用"，点击"查看使用记录"展开使用过该模块的活动或 Celebration 名称列表；从未被使用的模块显示"暂未被使用"而非报错或空白。
- AC-005：模块库不提供任何"新增模块类型"的入口（无按钮、无表单）。
