# 活动模块配置与模块库（module-002-admin）

## 1. 概述

活动内部的具体"玩法"（CEO致辞、历史时间轴、涂鸦评选、寄语墙、报名信息、周年博客列表）以"活动模块"的形式挂载在活动上，行政在创建活动流程第二步勾选启用哪些模块并配置参数。"模块库"是这些模块类型的只读参考目录，供行政配置前浏览参考。

**非目标**：不支持行政自定义新的模块类型；模块库不提供新增/删除模块类型的入口，新类型需要开发实现。

## 2. 涉及角色

引用 [`ROLES.md`](../../shared/ROLES.md)：仅行政操作本模块的配置与浏览。

## 3. 术语与模块归属

引用 [`GLOSSARY.md`](../../shared/GLOSSARY.md)：活动模块、模块库、开始展示时间。依赖 `activity-001-admin`（活动必须先存在才能挂载模块）。

## 4. 使用场景

- 行政创建活动时，在第二步勾选本次活动要启用的模块，并填写每个模块的专属参数（如涂鸦评选的提交/投票截止时间）。
- 行政配置前，先去模块库浏览"历史上这个模块被哪些活动用过、配置成什么样"作为参考。
- 行政希望某个板块（如历史时间轴）不要一发布就出现，而是活动当天才揭晓。

## 5. 业务流程与状态机

### 5.1 模块的两层状态

**启用状态**（是否挂载）：由行政在配置步骤的开关直接控制，不需要状态机——开则创建对应的活动模块记录，关则不创建/移除。

**展示与阶段状态**（挂载后，模块自身何时可见、内部处于什么阶段）：由时间戳字段计算得出，不做成需要人工点击切换的显式状态，具体规则：

```
当前时间 < 开始展示时间           → 模块整个不渲染（对用户不可见，不是禁用态）
开始展示时间 ≤ 当前时间 < 提交截止时间   → （若模块有提交环节）提交中
提交截止时间 ≤ 当前时间 < 投票截止时间   → （若模块有投票环节）投票中
当前时间 ≥ 最后一个截止时间          → 已结束（展示最终结果，只读）
```

未配置"提交/投票/留言截止时间"的模块（如 CEO致辞、历史时间轴），只有"开始展示时间"这一层判断，没有内部阶段流转。

### 5.2 涂鸦评选内部阶段细化

涂鸦评选当前版本作品来源为**行政上传**（非员工自主提交），因此没有"员工提交"这一开放阶段，行政可随时上传作品，"提交截止时间"实际控制的是"行政最后编辑作品列表的时间点"，"投票截止时间"控制员工投票窗口。此约束为当前版本的产品决策，非技术限制。

## 6. 数据对象

**活动模块（ActivityModule）**：某个活动实例启用的某一种玩法。归属某个模块类型（`module_type`），带有该活动此次启用时的专属配置（如涂鸦评选的截止时间、寄语墙的展示样式）、通用配置（开始展示时间、排序）、以及模块的分类属性（内容型：行政直接编辑发布的内容，如CEO致辞、历史时间轴、周年博客列表；互动型：需要收集用户交互的模块，如涂鸦评选、寄语墙、报名信息）。

**模块类型参考信息（模块库条目）**：每种模块类型的说明、可配置属性清单、历史使用记录，由开发维护，行政只读浏览，不属于可编辑的数据对象。

## 7. 权限规则

- 仅行政可以勾选启用/停用模块、填写模块配置参数，操作发生在活动仍处于可编辑状态（草稿/已驳回）时；活动进入审批中及之后状态，模块配置随活动一起锁定，不可单独修改（与 `activity-001-admin` §7 的编辑限制一致）。
- 模块库为全员行政只读，不区分更细的权限层级。

## 8. 校验规则

- 涂鸦评选：投票截止时间必须晚于提交截止时间。
- 寄语墙：留言截止时间若填写，必须晚于活动开始时间；若不填，视为与活动同时结束。
- 所有模块的"开始展示时间"若填写，不得晚于该模块自身的任何截止时间字段（如涂鸦评选的开始展示时间不能晚于提交截止时间），避免出现"模块还没开始展示，提交却已经截止"的逻辑矛盾。
- **联动校验（跨模块）**：当活动的"外部可见性"（见 `activity-001-admin`）为"仅内部可见"时，寄语墙的"允许外部人士留言"开关不应为"是"；提交/保存时给出提示，具体是阻止保存还是仅警告，属已知缺口（见 §11）。

## 9. 页面与状态清单

| 页面 | 需要的状态 |
|---|---|
| 配置活动模块（创建活动步骤二） | normal |
| 模块库 | normal / loading / empty(某模块类型从未被任何活动使用) |

## 10. 验收标准

- AC-001：勾选启用某个模块后，该模块的专属配置字段区域展开显示；取消勾选后配置区域收起，且已填写的值不提交（不创建对应活动模块记录）。
- AC-002：涂鸦评选的投票截止时间早于或等于提交截止时间时，保存时报错阻止。
- AC-003：任一模块设置"开始展示时间"晚于活动本身的"开始展示时间"上限（各自的截止时间字段）时，保存时报错阻止。
- AC-004：模块库中每张模块卡片展示"可配置属性"清单和"已被 N 个活动使用"，点击"查看使用记录"展开该模块被使用过的活动名称列表；从未被使用的模块显示"暂未被使用"而非报错或空白。
- AC-005：模块库不提供任何"新增模块类型"的入口（无按钮、无表单）。

## 11. 已知缺口与非目标

| 缺口 | 谁来定 | 何时前定 |
|---|---|---|
| 活动"外部可见性=仅内部"与模块"允许外部人士留言=是"冲突时，是阻止保存还是仅警告放行 | 行政 | 开发排期前 |
| 涂鸦评选未来若开放员工自主提交，"提交截止时间"的含义需要重新定义（从"行政编辑截止"变为"员工提交截止"），当前需求仅覆盖行政上传场景 | 行政 | 该功能立项时 |
| "开始展示时间"到达后是否需要主动推送通知，还是仅被动依赖用户下次访问页面时看到 | 行政 | 开发排期前 |
