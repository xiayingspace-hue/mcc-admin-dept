# 内部人员与外部人士的录入（directory-010-admin）

## 1. 概述

作品管理（上传 / 编辑作品）、报名管理（行政代报名）、寄语管理（行政代录入 / 编辑留言）这三处，行政都要先选择人员的类型：**内部员工**或**外部人士**。本需求统一定义这两种类型怎么录入：

- **外部人士**：手动输入姓名，部门 / 所属机构也手动输入（自由文本）。
- **内部员工**：不再手填。人员从 HR 系统里选择；所属（部门或项目）也从 HR 系统里选择，部门和项目的数据都来自 HR 系统。

**非目标**：
- 不改变员工在用户端自主报名、自主提交寄语时的身份来源（来自登录身份，见 `identity-009-admin`），本需求只管行政在管理端的录入。
- 不做 HR 数据的维护，管理端对 HR 的员工、部门、项目只读、只选。
- 不迁移历史记录（系统仍在使用阶段，已有记录里的自由文本部门 / 机构保持原样，历史数据可清理）。
- 不支持一条记录里内部员工与外部人士混合（作品团队同理，仍是一件作品一个类型）。

## 2. 涉及角色

引用 [`ROLES.md`](../../shared/ROLES.md)：行政。

## 3. 术语与模块归属

本需求使用的术语见 [`GLOSSARY.md`](../../shared/GLOSSARY.md)：作者类型、所属（部门或项目）。

被本需求约束的录入位置分别归属：作品上传 / 编辑（`submission-003-admin`）、行政代报名（`registration-004-admin`）、行政代录入 / 编辑留言（`wall-005-admin`）。三份文档只写各自特有的部分（人数、必填性），共有规则以本文档为准。

## 4. 使用场景

- 行政为一件团队涂鸦作品录入作者：选"内部员工"，在 HR 里搜索并选中几位同事，再为这件作品选一个所属部门或项目。
- 行政为一位合作伙伴代报名：选"外部人士"，手动输入姓名和公司名称。
- 行政为一位员工代报名或代录入留言：选"内部员工"，搜索并选中这位员工，所属默认带出他在 HR 里的部门，需要时可以改选别的部门或某个项目。

## 5. 业务流程与状态机

选择类型后，表单上的录入方式不同：

| 类型 | 姓名 | 所属（部门 / 机构） |
|---|---|---|
| 内部员工 | 在 HR 里搜索并选择员工（按姓名或工号），不能手填 | 在 HR 里选一个部门，或选一个项目（二选一），选填 |
| 外部人士 | 手动输入 | 手动输入部门 / 所属机构，自由文本，选填 |

切换类型时，已填写的另一种类型的内容被清空，不带到新类型里。

## 6. 数据对象

**人员信息（AuthorInfo）**：作品、报名记录、留言上记录"这个人是谁"的信息，包含：
- 作者类型：内部员工 / 外部人士。
- 内部员工：所选员工（来自 HR，含姓名、工号）、所属——部门（来自 HR）或项目（来自 HR），二选一，可以为空。
- 外部人士：姓名（手填）、部门 / 所属机构（手填的自由文本，可以为空）。

**HR 员工 / 部门 / 项目**：HR 系统里的数据，管理端只读、只选，不能在这里新增或修改。选择器里只出现有效的数据：员工只含在职员工（离职员工由后端自动过滤，不返回）；部门是有层级的，只能选末级部门，展示时只显示所选部门自己的名称（末级名称，不带上级路径）；项目只含有效项目（HR 里已关闭的项目不返回、不能再选）。HR 员工还带有联系电话、邮箱（仅管理端行政可见，目前只有报名管理的代报名用它们带出，见 `registration-004-admin`）。

**保存的是当时的值（快照）**：记录里保存的是选择那一刻的姓名和所属（以及代报名时带出的电话、邮箱）；之后 HR 里员工改名、调部门、项目关闭，已有记录不会跟着变。

## 7. 权限规则

- 只有行政能在管理端使用内部员工的选择；选择器能看到的员工信息（姓名、工号、部门）只在管理端显示。
- 用户端不使用本需求的选择器。

## 8. 校验规则

- **内部员工必须来自 HR**：员工、所属部门、所属项目都只能在选择器里选，不能手填；HR 里找不到时不能添加（需要先让 HR 补数据）。后端同样校验：新选择的员工必须是在职员工、部门必须是末级部门、项目必须是有效项目（以查询时 HR 的数据为准），伪造的标识、不符合条件的标识、直接传姓名文本的请求被拒绝。
- **所属二选一**：一条记录的所属只能是一个部门或一个项目，不能两个都有；可以为空。
- **默认带出**：为单个人（报名、留言、只有一位作者的作品）选中员工后，所属默认带出该员工在 HR 里的部门；行政可以改选其他部门或某个项目，也可以清空。多位作者的作品不自动带出（几位员工部门可能不同），由行政自己选择或留空。
- **外部人士**：姓名手填，规则沿用各模块原有规定（作品作者用逗号分隔等）；部门 / 机构自由文本，选填；外部人士的记录不得带 HR 的员工、部门、项目标识。
- **类型切换**：切换作者类型时清空另一种类型已填的内容。
- **HR 不可用**：HR 系统查询失败或超时时，选择器显示错误与"重试"，不提供手动输入作为兜底，已经选好的内容不丢失。
- **只返回有效数据**：后端返回员工时自动过滤掉离职员工，返回部门时只含末级部门，返回项目时只含有效项目；前端不再自己过滤，直接调用接口也拿不到这些无效数据。
- **保存快照**：保存时记录选择当时的姓名和所属，之后 HR 的变化不回写已有记录。
- **编辑已有记录**：编辑时显示已保存的值；没有改动的员工 / 所属原样保留，即使该员工后来已离职、该项目后来已关闭，也可以继续保存；行政新选择的员工和所属必须满足上面的有效性要求。
- **搜索**：员工按姓名或工号搜索，部门、项目按名称搜索；没有匹配时提示"HR 系统中没有匹配的……"。

## 9. 页面与状态清单

本需求不新增页面，给三处录入表单增加下面这几个选择器：

| 选择器（所在表单） | 需要的状态 |
|---|---|
| 员工选择（作品上传 / 编辑；行政代报名；留言代录入 / 编辑） | normal / loading(搜索中) / empty(没有匹配) / error(HR 查询失败，可重试) / overflow(姓名、部门名称很长，不撑破表单；作品已选多位员工时换行展示) |
| 部门 / 项目选择（同上） | normal / loading / empty(没有匹配) / error(可重试) / overflow |
| 外部人士的姓名、部门 / 机构输入（同上） | normal / error(沿用各模块的姓名校验) |

## 10. 验收标准

- AC-001：行政在上述三处表单里选"内部员工"时，姓名区域变为员工选择器（不再是文本输入框），所属区域变为部门 / 项目选择；选"外部人士"时，姓名为手动输入，部门 / 所属机构为自由文本输入框。
- AC-002：选"内部员工"后，行政可按姓名或工号搜索 HR 里的在职员工并选中；选中后显示姓名、工号、部门；不能手填员工姓名；搜索没有匹配时提示"HR 系统中没有匹配的员工"，无法添加不存在的人。离职员工不出现在搜索结果里（即使输入完整姓名或工号也搜不到）。
- AC-003：内部员工的所属只能选"一个部门"或"一个项目"，二者不能同时存在；部门、项目都来自 HR，搜索没有匹配时同样提示且不能手填；所属可以留空。部门只能选末级部门，已选部门只显示它自己的名称（不带上级路径）；HR 里已关闭的项目不出现在搜索结果里，不能选择。
- AC-004：为单个人选中员工后，所属默认带出该员工在 HR 里的部门；行政可以改选其他部门或某个项目，也可以清空；多位作者的作品选员工后不自动带出所属。
- AC-005：选"外部人士"时，部门 / 所属机构可以手动输入任意文本，也可以留空；外部人士的姓名规则沿用各模块原有规定。
- AC-006：切换作者类型时，已填写的另一种类型的内容被清空：从内部员工切到外部人士，已选的员工和所属被清掉；从外部人士切到内部员工，已手填的姓名和部门 / 机构被清掉。
- AC-007：保存时后端校验：新选择的员工必须是 HR 里的在职员工、部门必须是末级部门、项目必须是有效项目，不存在、已离职、非末级、已关闭的被拒绝；绕过页面直接传姓名文本冒充内部员工、或同时带部门和项目的，被拒绝，不产生记录；外部人士的记录带 HR 标识的被拒绝。
- AC-008：HR 系统查询失败或超时时，选择器显示错误与"重试"，不提供手动输入兜底；点击重试重新查询，成功后可正常选择；此前已选好的内容不丢失。
- AC-009：在列表、详情、名单里展示内部员工记录时，所属显示所选部门或项目的名称；外部人士显示手填的部门 / 机构；所属为空时展示方式沿用各模块原有规定。
- AC-010：已有记录不做迁移：改造前创建的记录里的自由文本部门 / 机构保持原样显示，不要求补选。
- AC-011：后端返回的员工、部门、项目都是有效数据：直接调用接口时，离职员工不会出现在员工列表里，非末级部门不会出现在部门列表里，已关闭的项目不会出现在项目列表里；前端不需要也不依赖自己过滤。
- AC-012：记录保存的是选择当时的姓名和所属：保存后 HR 里该员工改名、调部门、该项目关闭，已有记录显示的姓名和所属都不变，不需要也不会自动更新。
- AC-013：编辑已有记录时，没有改动的员工和所属原样保留并可保存，即使该员工后来已离职、该项目后来已关闭；行政重新选择员工或所属时，新选的必须符合有效性要求（AC-002、AC-003、AC-007）。
