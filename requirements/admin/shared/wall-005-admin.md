# 寄语墙管理（wall-005-admin）

## 1. 概述

员工在活动详情页自主提交寄语留言（一段文字加一张配图，可选匿名，并填写邮箱），行政审核决定哪些留言展示在活动页面；外部合作伙伴无系统账号，由行政代为录入其留言。本需求覆盖留言的提交、审核、展示状态管理；不覆盖用户端提交表单本身的交互细节（见待补充的 `user` 端需求文档）。

**非目标**：员工在用户端查看自己提交过的留言及其审核状态（「我的提交」）不做，用户端不提供该入口。

## 2. 涉及角色

引用 [`ROLES.md`](../../shared/ROLES.md)：行政（审核/代录入）、员工（自主提交，用户端行为）。

## 3. 术语与模块归属

依赖 `module-002-admin`（寄语墙类型的活动模块必须已启用）。**例外**：已发布活动的寄语墙被停用后（见 `activity-011-admin`），行政仍可在本模块审核、隐藏、编辑该活动已有的历史留言；停用只影响用户页面是否显示寄语墙，不影响本模块的管理。

## 4. 使用场景

- 员工在活动详情页写一句祝福留言，并配一张图片（必填，仅一张），填写邮箱，可选择匿名。
- 行政审核收到的留言，决定哪些展示在活动页面、哪些不展示（如内容不合适）。
- 行政为外部合作伙伴代录入一条留言（该合作伙伴口头或邮件表达祝福，行政帮忙录入并配图）。
- 行政按活动、按状态筛选查看全部留言。
- 行政发现某条留言不该留在列表里（如审核后确认无需保留的待审核留言，或已隐藏、不再需要恢复的留言），点击「删除」并确认，该留言从管理端列表中移除。

## 5. 业务流程与状态机

| 当前状态 | 触发动作 | 下一状态 |
|---|---|---|
| （新建）| 员工自主提交 / 行政代录入 | `待审核` |
| `待审核` | 行政点击"展示" | `已展示` |
| `待审核` | 行政点击"拒绝" | `已隐藏` |
| `已展示` | 行政点击"隐藏" | `已隐藏` |
| `已隐藏` | 行政点击"恢复" | `已展示` |
| `待审核` / `已隐藏` | 行政点击"编辑"并保存 | 状态不变（不会自动重新审核；`已展示`的留言需先隐藏才能编辑） |
| `待审核` / `已隐藏` | 行政点击"删除"并二次确认 | `已删除`（终态，软删除，见下） |

`已展示`状态的留言出现在活动详情页寄语墙板块；其余状态不出现。`已隐藏`的留言内容对外展示为"该留言因含不适宜内容已被隐藏"占位文案，原文不删除（软删除，见 `conventions.md`）。

**邮箱**：员工自主提交时填写的邮箱，本期只保存，不用于发送任何邮件（审核通过或拒绝都不通知提交人），也不展示，见 §7。

**删除**：`已删除`是终态，记录仍保留在数据库中（软删除），但从管理端留言列表、筛选与状态统计、用户端、数据统计中全部消失，管理端不提供恢复入口。`已隐藏`与`已删除`的区别：隐藏可以由行政随时恢复，删除不可恢复。`已隐藏`状态既包括从未展示过就被拒绝的留言，也包括展示过后又被隐藏的留言，两种都可以删除。`已展示`的留言不能直接删除，需先隐藏。

## 6. 数据对象

**寄语（WallMessage）**：归属某个活动模块（寄语墙类型）的一条留言记录。包含留言文本（必填）、配图（必填，且仅 1 张，JPG 或 PNG，不超过 5MB）、邮箱（员工自主提交时必填；行政代录入外部人士的留言，录入的邮箱地址同样必填；行政代录入内部员工的留言没有该项；本期只保存，不发送邮件，展示范围见 §7）、作者信息（作者类型：内部员工/外部人士；行政代录入时，内部员工从 HR 系统选择、所属为 HR 的一个部门或项目，外部人士手动输入姓名、公司名称与职位（均必填；公司名称取代其他模块里的“部门 / 机构”，这是寄语管理的例外），规则见 `directory-010-admin`；若匿名则不展示真实姓名，展示"匿名员工"）、审核状态、编辑留痕（被行政修改过的留言带"已编辑"标记，以及修改人、修改时间；只保留最后一次的修改人与时间，不保存历史版本）。被删除的寄语记录继续保留（包括匿名留言的真实提交人关联），只是不再对管理端和用户端展示，也不计入数据统计；同时记录删除人（行政）与删除时间，本期只记录，不在任何页面展示。

## 7. 权限规则

- 员工只能提交留言（用户端权限），不能审核他人留言。
- 用户端提交寄语只有员工可以进行，外部人员不能自主提交，提交入口不显示（外部人士的留言由行政代录入）；身份识别、置灰提示与后端拒绝规则见 `identity-009-admin`，本文档不重复定义。
- 行政可以查看全部留言、执行展示/拒绝/隐藏/恢复、代外部人士录入留言。
- 行政可以编辑"待审核""已隐藏"状态的留言（员工自主提交的和行政代录入的都可以）；"已展示"状态没有编辑入口，需先隐藏再编辑，后端同样拒绝对已展示留言的编辑。
- 任一行政都可以删除"待审核""已隐藏"状态的留言（员工自主提交的和行政代录入的都可以）；"已展示"状态没有删除入口，需先隐藏再删除，后端同样拒绝对已展示留言的删除。员工不能删除留言（包括自己提交的）；员工不会因留言被删除收到通知，删除对员工没有可见影响。
- 邮箱本期只保存，不用于发送任何邮件。员工自主提交的邮箱不在管理端和用户端的任何位置展示，行政也不能查看或修改；行政代录入外部人士留言时填写的邮箱，只出现在代录入表单与编辑表单里（行政可回显、可修改），不在管理端列表和用户端展示。
- 可修改的内容：留言文字、配图。员工自主提交的留言，作者身份和"是否匿名"不可修改；行政代录入的留言，作者姓名、作者类型、所属也可以修改，外部人士还可以修改公司名称、职位、邮箱地址。

## 8. 校验规则

- 员工自主提交：留言内容必填；**邮箱必填**，格式与长度规则同 `registration-004-admin` AC-006（为空、缺少 @ 或域名、超过 100 个字符被阻止并提示），前端拦截 + 后端二次校验，匿名提交同样必填；**配图必填且仅 1 张**，仅限 JPG 或 PNG，不超过 5MB；匿名选项选填。已选一张后再选新图，替换原图；也可删除后重新上传。前端拦截 + 后端二次校验。
- 行政代录入：先选作者类型；内部员工须从 HR 系统选中一位员工（所属默认带出其 HR 部门，可改选其他部门或某个项目，选填），外部人士手动输入作者姓名、公司名称、职位、邮箱地址，**四项均必填**（邮箱规则同 `registration-004-admin` AC-006：为空、缺少 @ 或域名、超过 100 个字符被阻止并提示；公司名称、职位的长度上限见 §11），前端拦截 + 后端二次校验；留言内容必填；配图同样必填且仅 1 张（JPG 或 PNG，不超过 5MB），与员工提交路径一致。

- 删除：仅"待审核""已隐藏"状态允许，执行前必须二次确认（确认前不产生任何改动）；后端校验状态，留言已被他人改为"已展示"、或已被删除时，删除被拒绝并提示"留言状态已变化，请刷新"，列表重新加载；删除请求失败时留言保持原状，提示失败并可重试。
- 编辑保存时：留言内容必填；配图必填且仅 1 张（规则同员工提交，JPG 或 PNG、不超过 5MB），原来没有配图的历史留言，保存时也必须补上；匿名的留言修改后仍然匿名，管理端列表继续显示"匿名员工"。前端拦截 + 后端二次校验。

## 9. 页面与状态清单

| 页面 | 需要的状态 |
|---|---|
| 寄语墙管理（代录入表单 + 留言列表） | normal / loading / empty(该活动模块下没有留言：从未收到过，或留言全部被删除后) / empty(筛选无结果) / error(代录入未传配图、格式或大小不符；外部人士的姓名、公司名称、职位、邮箱地址缺项或邮箱不合格) / loading(配图上传中) |
| 删除留言确认弹窗（行政） | normal / loading(删除请求中) / error(删除失败可重试；留言状态已变化) |
| 编辑留言表单（行政） | normal / loading(配图上传中) / error(留言内容为空、未上传配图、配图格式或大小不符、外部人士必填项缺失或邮箱不合格) / 保存成功 |
| 用户端「写下你的寄语」弹窗 | normal / loading(配图上传中) / error(邮箱为空、格式不符或超长、未上传配图、配图格式或大小不符、一次选了多张、上传失败可重试、留言内容为空) / 提交成功(提示需行政审核后才会展示) |

## 10. 验收标准

- AC-001：点击"展示"后状态变为"已展示"；点击"拒绝"或"隐藏"后状态变为"已隐藏"，原文保留、对外展示为占位文案。
- AC-002：按活动筛选和按状态筛选同时生效（交集），状态变化后当前筛选自动重新应用。
- AC-003：勾选"匿名提交"的留言，管理端列表展示"匿名员工"而非真实姓名，但行政后台内部仍保留真实提交人的关联（供滥用追责，不对外展示）。
- AC-004：【已废止，编号留空不复用】原"配图选填"规则已取消，配图改为必填且仅 1 张，由 AC-006～AC-009 取代。
- AC-005：员工在用户端提交留言后，若活动的寄语墙已到"留言截止时间"（见 `module-002-admin`），提交入口应不可用；本需求管理端不重复实现该判断，仅消费其结果（截止后的留言列表不再新增待审核记录）。
- AC-006：员工在用户端"写下你的寄语"弹窗提交时，配图必填：没有上传配图点击"提交"被阻止并提示"请上传配图"；匿名提交同样必须配图。
- AC-007：配图仅限 1 张，JPG 或 PNG，不超过 5MB；格式不符、超过大小、一次选了多张的，被拒绝并提示具体原因（类型不支持 / 超过 5MB / 只能上传 1 张）；已选一张后再选新图，直接替换原图；可以删除后重新上传；上传失败显示失败状态与"重试"。
- AC-008：行政在管理端代录入留言时，配图同样必填且仅 1 张，规则与 AC-006、AC-007 一致，缺少配图点击"提交留言"被阻止。
- AC-009：配图的必填与格式、大小、数量限制由后端二次校验，绕过前端直接调用提交接口（用户端提交与行政代录入）缺图、多图、格式不符或超大的，被拒绝并返回明确原因；列表和寄语墙板块展示的每条留言都带配图，图片完整显示、不拉伸、不造成布局错乱。
- AC-010：管理端留言列表中，"待审核"和"已隐藏"状态的留言有"编辑"入口，"已展示"状态没有；对已展示留言直接调用编辑接口被后端拒绝，留言内容不变。
- AC-011：编辑员工自主提交的留言时，可修改留言文字和配图，作者身份和"是否匿名"只读不可改；编辑行政代录入的留言时，作者姓名、作者类型、所属也可以修改，外部人士还可以修改公司名称、职位、邮箱地址（见 AC-034）；员工提交的留言，直接调用接口修改作者字段被后端拒绝。
- AC-012：编辑保存时，留言内容为空、没有配图（含原本就没有配图的历史留言）、配图格式或大小不符、一次选多张，保存被阻止并提示具体原因；保存成功后留言状态不变，不自动回到待审核。
- AC-013：被行政修改过的留言，管理端列表显示"已编辑"标记，鼠标悬停可看修改人和修改时间；只记录最后一次的修改人与时间，不保存历史版本；不通知员工。
- AC-014：匿名提交的留言被行政编辑后仍然匿名，管理端列表继续显示"匿名员工"，真实提交人的关联保持不变（同 AC-003）。
- AC-015：用户端提交寄语只有员工可以进行：外部人员（含从公司官网进入的访问者）看不到「写下你的寄语」按钮，也没有任何提示文字（已展示的寄语照常显示）；绕过页面直接调用提交接口被后端拒绝，不产生留言。规则与展示见 `identity-009-admin` AC-002、AC-003、AC-005；行政代录入不受影响。
- AC-016：寄语管理列表里所有留言默认按创建时间（提交的时间，员工提交或行政代录入）倒序排列，最新的在最前；与活动、状态筛选同时生效（先筛选再排序），翻页不重复不遗漏；展示 / 拒绝 / 隐藏 / 恢复和编辑都不改变留言在列表中的位置；新提交的留言出现在最前。规则见 `conventions.md`「列表默认排序」。
- AC-017：行政代录入或编辑留言时，作者类型为"内部员工"需在 HR 系统里搜索并选中一位员工（不能手填姓名），所属默认带出其 HR 部门，可改选其他部门或某个项目，也可留空；为"外部人士"时手动输入姓名、公司名称、职位、邮箱地址（均必填，见 AC-031）。未选中员工（内部员工）或姓名为空（外部人士）点击提交被阻止。通用规则见 `directory-010-admin` AC-001～AC-009；员工自主提交的留言作者仍来自登录身份，不使用选择器。
- AC-018：管理端留言列表中，"待审核"和"已隐藏"状态的留言有"删除"入口，"已展示"状态没有；对已展示留言直接调用删除接口被后端拒绝，留言保持原状；先隐藏后再删除则可以。
- AC-019：点击"删除"弹出二次确认，文案说明留言将从列表中移除且无法在管理端恢复；点击"取消"或关闭弹窗，留言不变；点击确认后留言从列表消失，列表停留在当前页刷新，当前页被删空时自动回到新的末页（见 `conventions.md` 分页），顶部状态统计（待审核 / 已展示 / 已隐藏）同步减少，当前筛选条件保持。
- AC-020：从未展示过的已隐藏留言（被拒绝）与展示过后又被隐藏的留言，都可以删除；被删除的留言在用户端不展示，行政也不再能在列表中查到。
- AC-021：删除是软删除：被删除留言的记录仍保留在数据库中，匿名留言的真实提交人关联同样保留（见 AC-003）；删除时同时记录删除人（行政）与删除时间；管理端没有任何恢复已删除留言的入口。
- AC-022：被删除的留言不计入数据统计里的留言数（见 `stats-006-admin`），删除后该活动的留言数立即扣减；删除"待审核""已隐藏"的留言，不影响其他留言的状态与位置。
- AC-023：两位行政同时操作同一条留言，一人已将其改为"已展示"（或已删除）后，另一人再点击"删除"被后端拒绝并提示"留言状态已变化，请刷新"，刷新后看到最新状态；删除请求失败（网络或服务端错误）时，留言保持原状，提示失败并可重试，不出现"列表已移除、实际未删除"的不一致。

- AC-024：寄语管理列表没有任何留言时（从未收到过，或留言全部被删除后）显示空态"暂无留言"及说明；有留言但当前筛选下没有结果时显示"没有符合条件的留言"及说明，两种文案不同；删除导致列表变空时立即按上述规则切换为对应空态，不出现空白列表。空态下顶部状态统计仍显示（均为 0 或当前实际数）。

- AC-025：员工在用户端打开"写下你的寄语"弹窗，表单顶部显示说明"行政审核通过后才会展示在寄语墙"；提交成功后弹窗切换为成功页，显示"提交成功"和"行政审核通过后将展示在寄语墙"，点击"OK"关闭弹窗；匿名提交同样显示。提交未通过校验（留言内容为空、邮箱不合格、缺配图、配图不符等）或上传、提交失败时，不显示成功页，保持在表单并提示原因。提交成功后该留言状态为"待审核"，不会立即出现在用户端寄语墙，直到行政点击"展示"。页面不提示审核结果会通过邮件或其他方式通知。
- AC-026：用户端"写下你的寄语"弹窗有"邮箱"输入框，必填；默认带出该员工在 HR 里的邮箱（HR 里没有则为空），员工可修改；为空、格式不符（缺少 @ 或域名）、超过 100 个字符时，点击"提交"被阻止并在邮箱框旁提示具体原因，与其他校验错误可同时提示；匿名提交同样必填；绕过前端直接调用提交接口缺少或不符合要求的邮箱被后端拒绝并返回明确原因，不产生留言。邮箱本期只保存，不发送邮件（见 §5）。
- AC-027：【已废止，编号留空不复用】原"审核通过 / 拒绝后向提交人发送审核结果邮件"已取消，审核结果不再通过邮件通知。
- AC-028：【已废止，编号留空不复用】原"哪些操作不发邮件"随邮件通知一并取消；审核、隐藏、恢复、编辑、删除都不发送任何邮件。
- AC-029：【已废止，编号留空不复用】原"邮件发送失败不影响审核"随邮件通知一并取消。
- AC-030：员工自主提交的邮箱不在管理端留言列表、编辑表单和用户端的任何位置展示；行政代录入外部人士留言的邮箱，只在代录入表单与编辑表单里出现，不在列表和用户端展示；任何审核操作（展示、拒绝、隐藏、恢复）都不会向这些邮箱发送邮件。
- AC-031：行政在代录入表单或编辑表单里选作者类型"外部人士"时，表单有姓名、公司名称、职位、邮箱地址四项输入，均必填；任一项为空，点击提交（保存）被阻止并指出缺哪一项；邮箱为空、缺少 @ 或域名、超过 100 个字符时提示具体原因；选"内部员工"时表单不出现公司名称、职位、邮箱地址这三项。后端二次校验：绕过页面直接调用接口缺少任一项、或邮箱不合格的，被拒绝并返回明确原因，不产生或修改留言。
- AC-032：凡原来显示外部人士"部门 / 机构"的位置（管理端寄语列表的作者信息、用户端寄语卡片的作者所属行），改为显示"公司名称 · 职位"；邮箱地址在这些位置都不显示；内部员工的显示规则不变。
- AC-033：【已废止，编号留空不复用】原"行政代录入的外部人士留言审核时向其邮箱发邮件"已取消；该邮箱仍必填、仍保存（见 AC-031），只是不发邮件。
- AC-034：编辑行政代录入的外部人士留言（待审核 / 已隐藏）时，表单回显姓名、公司名称、职位、邮箱地址，均可修改；把作者类型从"外部人士"切到"内部员工"时，已填的公司名称、职位、邮箱地址被清空，该留言此后没有邮箱。本规则上线前录入的外部人士留言（原来只有部门 / 机构文本），编辑时原有的部门 / 机构文本带入"公司名称"，职位与邮箱为空，保存前必须补全。
