# 寄语墙管理（wall-005-admin）

## 1. 概述

员工在活动详情页自主提交寄语留言（一段文字加一张配图，可选匿名），行政审核决定哪些留言展示在活动页面；外部合作伙伴无系统账号，由行政代为录入其留言。本需求覆盖留言的提交、审核、展示状态管理；不覆盖用户端提交表单本身的交互细节（见待补充的 `user` 端需求文档）。

## 2. 涉及角色

引用 [`ROLES.md`](../../shared/ROLES.md)：行政（审核/代录入）、员工（自主提交，用户端行为）。

## 3. 术语与模块归属

依赖 `module-002-admin`（寄语墙类型的活动模块必须已启用）。

## 4. 使用场景

- 员工在活动详情页写一句祝福留言，并配一张图片（必填，仅一张），可选择匿名。
- 行政审核收到的留言，决定哪些展示在活动页面、哪些不展示（如内容不合适）。
- 行政为外部合作伙伴代录入一条留言（该合作伙伴口头或邮件表达祝福，行政帮忙录入并配图）。
- 行政按活动、按状态筛选查看全部留言。

## 5. 业务流程与状态机

| 当前状态 | 触发动作 | 下一状态 |
|---|---|---|
| （新建）| 员工自主提交 / 行政代录入 | `待审核` |
| `待审核` | 行政点击"展示" | `已展示` |
| `待审核` | 行政点击"拒绝" | `已隐藏` |
| `已展示` | 行政点击"隐藏" | `已隐藏` |
| `已隐藏` | 行政点击"恢复" | `已展示` |
| `待审核` / `已隐藏` | 行政点击"编辑"并保存 | 状态不变（不会自动重新审核；`已展示`的留言需先隐藏才能编辑） |

`已展示`状态的留言出现在活动详情页寄语墙板块；其余状态不出现。`已隐藏`的留言内容对外展示为"该留言因含不适宜内容已被隐藏"占位文案，原文不删除（软删除，见 `conventions.md`）。

## 6. 数据对象

**寄语（WallMessage）**：归属某个活动模块（寄语墙类型）的一条留言记录。包含留言文本（必填）、配图（必填，且仅 1 张，JPG 或 PNG，不超过 5MB）、作者信息（作者类型：内部员工/外部人士；若匿名则不展示真实姓名，展示"匿名员工"）、审核状态、编辑留痕（被行政修改过的留言带"已编辑"标记，以及修改人、修改时间；只保留最后一次的修改人与时间，不保存历史版本）。

## 7. 权限规则

- 员工只能提交/查看自己的留言提交状态（用户端权限），不能审核他人留言。
- 行政可以查看全部留言、执行展示/拒绝/隐藏/恢复、代外部人士录入留言。
- 行政可以编辑"待审核""已隐藏"状态的留言（员工自主提交的和行政代录入的都可以）；"已展示"状态没有编辑入口，需先隐藏再编辑，后端同样拒绝对已展示留言的编辑。
- 可修改的内容：留言文字、配图。员工自主提交的留言，作者身份和"是否匿名"不可修改；行政代录入的留言，作者姓名、作者类型、部门也可以修改。

## 8. 校验规则

- 员工自主提交：留言内容必填；**配图必填且仅 1 张**，仅限 JPG 或 PNG，不超过 5MB；匿名选项选填。已选一张后再选新图，替换原图；也可删除后重新上传。前端拦截 + 后端二次校验。
- 行政代录入：作者姓名必填；留言内容必填；配图同样必填且仅 1 张（JPG 或 PNG，不超过 5MB），与员工提交路径一致。
- 联动校验：若活动"外部可见性"为"仅内部可见"，寄语墙"允许外部人士留言"开关不应为"是"（同 `module-002-admin` §8，此处重复引用不重复定义，具体阻止/警告方式以该文档裁决为准）。

- 编辑保存时：留言内容必填；配图必填且仅 1 张（规则同员工提交，JPG 或 PNG、不超过 5MB），原来没有配图的历史留言，保存时也必须补上；匿名的留言修改后仍然匿名，管理端列表继续显示"匿名员工"。前端拦截 + 后端二次校验。

## 9. 页面与状态清单

| 页面 | 需要的状态 |
|---|---|
| 寄语墙管理（代录入表单 + 留言列表） | normal / loading / empty(该活动模块下从未收到留言) / empty(筛选无结果) / error(代录入未传配图、格式或大小不符) / loading(配图上传中) |
| 编辑留言表单（行政） | normal / loading(配图上传中) / error(留言内容为空、未上传配图、配图格式或大小不符) / 保存成功 |
| 用户端「写下你的寄语」弹窗 | normal / loading(配图上传中) / error(未上传配图、配图格式或大小不符、一次选了多张、上传失败可重试、留言内容为空) / 提交成功 |

## 10. 验收标准

- AC-001：点击"展示"后状态变为"已展示"；点击"拒绝"或"隐藏"后状态变为"已隐藏"，原文保留、对外展示为占位文案。
- AC-002：按活动筛选和按状态筛选同时生效（交集），状态变化后当前筛选自动重新应用。
- AC-003：勾选"匿名提交"的留言，管理端列表展示"匿名员工"而非真实姓名，但行政后台内部仍保留真实提交人的关联（供滥用追责，不对外展示）。
- AC-004：【已废止，编号留空不复用】原"配图选填"规则已取消，配图改为必填且仅 1 张，由 AC-006～AC-009 取代。
- AC-005：员工在用户端提交留言后，若活动的寄语墙已到"留言截止时间"（见 `module-002-admin`），提交入口应不可用；本需求管理端不重复实现该判断，仅消费其结果（截止后的留言列表不再新增待审核记录）。
- AC-006：员工在用户端"写下你的寄语"弹窗提交时，配图必填：没有上传配图点击"提交"被阻止并提示"请上传配图"；匿名提交同样必须配图。
- AC-007：配图仅限 1 张，JPG 或 PNG，不超过 5MB；格式不符、超过大小、一次选了多张的，被拒绝并提示具体原因（类型不支持 / 超过 5MB / 只能上传 1 张）；已选一张后再选新图，直接替换原图；可以删除后重新上传；上传失败显示失败状态与"重试"。
- AC-008：行政在管理端代录入留言时，配图同样必填且仅 1 张，规则与 AC-006、AC-007 一致，缺少配图点击"提交留言"被阻止。
- AC-009：配图的必填与格式、大小、数量限制由后端二次校验，绕过前端直接调用提交接口（用户端提交与行政代录入）缺图、多图、格式不符或超大的，被拒绝并返回明确原因；列表和寄语墙板块展示的每条留言都带配图，图片完整显示、不拉伸、不造成布局错乱。
- AC-010：管理端留言列表中，"待审核"和"已隐藏"状态的留言有"编辑"入口，"已展示"状态没有；对已展示留言直接调用编辑接口被后端拒绝，留言内容不变。
- AC-011：编辑员工自主提交的留言时，可修改留言文字和配图，作者身份和"是否匿名"只读不可改；编辑行政代录入的留言时，作者姓名、作者类型、部门也可以修改；员工提交的留言，直接调用接口修改作者字段被后端拒绝。
- AC-012：编辑保存时，留言内容为空、没有配图（含原本就没有配图的历史留言）、配图格式或大小不符、一次选多张，保存被阻止并提示具体原因；保存成功后留言状态不变，不自动回到待审核。
- AC-013：被行政修改过的留言，管理端列表显示"已编辑"标记，鼠标悬停可看修改人和修改时间；只记录最后一次的修改人与时间，不保存历史版本；不通知员工。
- AC-014：匿名提交的留言被行政编辑后仍然匿名，管理端列表继续显示"匿名员工"，真实提交人的关联保持不变（同 AC-003）。

## 11. 已知缺口与非目标

| 缺口 | 谁来定 | 何时前定 |
|---|---|---|
| 匿名留言是否需要防滥用机制（如同一账号短时间内多次匿名提交的限制） | 行政 | 开发排期前 |
| 活动结束后，若"外部可见性"从开放改为仅内部，已展示的外部人士留言是否需要一并隐藏 | 行政 | 开发排期前，与 `activity-001-admin` §11 联动决定 |
| 是否需要展示排序/置顶能力（如把领导的留言排在最前） | 行政 | 开发排期前 |
| 员工留言被行政修改后，员工本人在"我的提交"里看到的是改后的还是原文、是否需要告知员工、是否需要保留修改历史（当前：看到改后的、不通知、不保留历史） | 行政 | 开发排期前 |
