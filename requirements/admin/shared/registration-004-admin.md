# 报名管理（registration-004-admin）

## 1. 概述

员工在活动详情页自主报名参加活动，行政在管理端查看报名名单、执行现场签到、并可为无系统账号的外部人士手动代报名。

## 2. 涉及角色

引用 [`ROLES.md`](../../shared/ROLES.md)：行政（查看/签到/代报名/取消）、员工（自主报名/取消，用户端行为）。

## 3. 术语与模块归属

依赖 `celebration-007-admin`（报名信息类型的模块必须已在某个 Celebration 下启用；报名记录归属该 Celebration，不再直接归属活动，同一活动下不同 Celebration 的报名数据相互独立）。报名信息模块的类型说明仍可在 `module-002-admin` 的模块库中查阅。参与范围（见 `activity-001-admin`）决定哪些员工在用户端能看到报名入口，本需求不重复定义该边界，只消费其结果。

## 4. 使用场景

- 员工在某个 Celebration 详情页填写联系电话、邮箱地址等信息完成报名。
- 行政查看某个 Celebration 的报名统计（已报名人数、已签到人数），现场活动当天逐一签到；同一活动下不同 site 的报名数据分开查看。
- 行政为无系统账号的外部合作伙伴手动录入一条报名记录。
- 员工报名后又想取消。

## 5. 业务流程与状态机

| 当前状态 | 触发动作 | 下一状态 |
|---|---|---|
| （新建）| 员工自主报名 / 行政手动代报名 | `未签到` |
| `未签到` | 行政执行签到 | `已签到` |
| `已签到` | 行政撤销签到 | `未签到` |
| `未签到` / `已签到` | 取消报名（员工自主或行政操作） | 记录移除 |

## 6. 数据对象

**报名记录（Registration）**：归属某个 Celebration 下挂载的报名信息模块的一条报名记录。包含报名人信息（类型：内部员工/外部人士；姓名；部门或头衔——内部员工理论上可关联员工档案自动带出，外部人士为自由文本）、联系方式（联系电话）、邮箱地址、报名时间、签到状态、备注（选填，如特殊饮食需求）。

**报名信息模块配置**：挂载在某个 Celebration 上的报名信息模块自身的配置，包含报名截止时间（选填）、名额上限（选填，留空表示不限）。二者均为 CelebrationModule 的专属字段，定义于本文档，供 `celebration-007-admin` 引用。

## 7. 权限规则

- 员工只能报名/取消自己的报名记录，不能查看或操作他人的报名记录（用户端权限，本需求管理端部分只关心行政视角）。
- 行政可以查看全部报名记录、执行签到/撤销签到/取消任意一条记录、手动新增代报名记录。

## 8. 校验规则

- 员工自主报名：联系电话必填且需符合手机号格式（11位数字）；邮箱地址必填，需符合邮箱格式（包含 @ 和域名），不超过 100 个字符，由员工手动填写（不从员工档案自动带出），前端拦截 + 后端二次校验；备注选填。
- 行政手动代报名：姓名必填，部门/头衔选填（留空展示为"—"），联系电话选填（外部人士的号码格式不一，不校验格式，留空展示为"—"），邮箱选填（留空展示为"—"，填写了则同样校验格式和长度）；手动代报名时须先选择归属的 Celebration，为必填项。
- 取消报名为不可逆操作，执行前需二次确认。
- 报名信息模块配置：报名截止时间、名额上限均为选填，填写时不做与其他字段的联动校验；名额已满后的行为见本节下一条，报名截止后的行为见 §11 已知缺口。
- **名额已满**：名额上限已设置，且该 Celebration 当前报名人数（含行政代报名，不论是否已签到）达到上限时：用户端 Celebration 详情页的「立即报名」按钮文案改为「报名人数已达上限」，置灰不可点击，无法再打开报名弹窗；后端同样拒绝新的员工自主报名（不依赖按钮状态）；有人取消报名使人数低于上限后，按钮自动恢复为「立即报名」；已经报名的员工仍显示「已报名 ✓」，不受影响。名额上限留空表示不限，永远不会触发。不支持排队候补。**行政手动代报名同样不允许超出名额上限**：名额已满时，管理端提交代报名被阻止并提示「报名人数已达上限，无法再添加报名」，后端同样拒绝；需要增加人数时，先由行政调大名额上限（在 Celebration 的报名信息配置里），或取消其他报名释放名额。

## 9. 页面与状态清单

| 页面 | 需要的状态 |
|---|---|
| 报名管理（统计 + 名单 + 按 Celebration 筛选 + 手动添加表单） | normal / loading / empty(该 Celebration 尚无人报名) |
| 用户端报名弹窗（姓名、部门自动带出，填写联系电话与邮箱） | normal / error(联系电话或邮箱校验失败，可同时提示) / 报名成功 |

## 10. 验收标准

- AC-001：点击"签到"后状态变为"已签到"，"已签到"统计数字同步 +1；点击"撤销签到"反向操作，统计数字 -1。
- AC-002：点击"取消报名"需二次确认（原地展示确认提示，不依赖浏览器原生弹窗），确认后该记录从列表移除，"已报名"统计 -1，若取消时该记录为"已签到"状态，"已签到"统计也同步 -1。
- AC-003：手动添加代报名时，未选择 Celebration 或姓名为空点击提交被阻止；提交成功后新记录出现在列表最上方并标注所属 Celebration，"已报名"统计 +1，表单自动清空并收起。
- AC-004：员工在用户端提交报名成功后，该条记录应能在管理端报名名单中查询到，且归属正确的 Celebration（前后端数据一致，非两套独立数据）。
- AC-005：报名管理列表的每一行均展示其所属 Celebration，按 Celebration 筛选后仅显示对应记录，切换筛选立即生效。
- AC-006：员工在用户端报名弹窗中填写邮箱地址，邮箱必填；为空、格式不符（缺少 @ 或域名）、超过 100 个字符时，点击"确认报名"被阻止并提示；联系电话与邮箱同时有误时，两处错误一并提示；全部通过才报名成功。
- AC-007：管理端报名名单新增"邮箱"列，展示每条报名记录的邮箱地址；员工自主报名的邮箱必有值，行政代报名未填写邮箱时展示"—"。
- AC-008：行政手动代报名时邮箱为选填；填写了邮箱则校验格式与长度，不符被阻止并提示；不填可正常提交。
- AC-009：名额上限已设置且报名人数（含行政代报名）达到上限时，用户端「立即报名」按钮文案变为「报名人数已达上限」并置灰不可点击，点击不会打开报名弹窗；人数未达上限（如 49/50）仍显示「立即报名」；名额上限留空时不会出现该状态；已报名的员工显示「已报名 ✓」而不是「报名人数已达上限」。
- AC-010：名额已满后，若有人取消报名使人数低于上限，用户端按钮自动恢复为「立即报名」，无需刷新配置或人工操作。
- AC-011：名额已满时，员工绕过页面直接调用报名接口被后端拒绝并返回「报名人数已达上限」，不产生报名记录；剩余名额只有 1 个时两人同时报名，只有一人成功，另一人收到已满提示，报名人数不超过名额上限。
- AC-012：管理端报名名单新增"联系电话"列，展示报名时填写的联系电话；员工自主报名的记录必有值，行政手动代报名未填写时展示"—"；手动添加表单提供选填的"联系电话"输入框，填写后该记录在名单里显示所填号码（不校验格式）。联系电话只在管理端对行政展示，不对其他员工展示。
- AC-013：名额已满时，行政在管理端手动添加代报名被阻止并提示「报名人数已达上限，无法再添加报名」，不产生报名记录，报名名单和人数不变；绕过页面直接调用代报名接口同样被后端拒绝；调大名额上限或取消其他报名使人数低于上限后，可以继续添加。人数统计包含行政代报名，不论是否已签到。

## 11. 已知缺口与非目标

| 缺口 | 谁来定 | 何时前定 |
|---|---|---|
| 签到方式是否需要支持现场扫码，而不仅是管理端手动点击 | 行政 | 开发排期前 |
| 报名截止时间到达后，用户端报名表单是变为只读、隐藏，还是仅提示已截止 | 行政 | 开发排期前 |
