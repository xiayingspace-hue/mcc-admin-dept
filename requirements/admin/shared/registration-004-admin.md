# 报名管理（registration-004-admin）

## 1. 概述

员工在活动详情页自主报名参加活动，行政在管理端查看报名名单、执行现场签到、并可为无系统账号的外部人士手动代报名。

## 2. 涉及角色

引用 [`ROLES.md`](../../shared/ROLES.md)：行政（查看/签到/代报名/取消）、员工（自主报名/取消，用户端行为）。

## 3. 术语与模块归属

依赖 `module-002-admin`（报名信息类型的活动模块必须已启用）。参与范围（见 `activity-001-admin`）决定哪些员工在用户端能看到报名入口，本需求不重复定义该边界，只消费其结果。

## 4. 使用场景

- 员工在活动详情页填写联系电话等信息完成报名。
- 行政查看某活动的报名统计（已报名人数、已签到人数），现场活动当天逐一签到。
- 行政为无系统账号的外部合作伙伴手动录入一条报名记录。
- 员工报名后又想取消。

## 5. 业务流程与状态机

| 当前状态 | 触发动作 | 下一状态 |
|---|---|---|
| （新建）| 员工自主报名 / 行政手动代报名 | `未签到` |
| `未签到` | 行政执行签到 | `已签到` |
| `已签到` | 行政撤销签到 | `未签到` |
| `未签到` / `已签到` | 取消报名（员工自主或行政操作） | 记录移除 |

## 6. 数据对象

**报名记录（Registration）**：归属某个活动模块（报名信息类型）的一条报名记录。包含报名人信息（类型：内部员工/外部人士；姓名；部门或头衔——内部员工理论上可关联员工档案自动带出，外部人士为自由文本）、联系方式、报名时间、签到状态、备注（选填，如特殊饮食需求）。

## 7. 权限规则

- 员工只能报名/取消自己的报名记录，不能查看或操作他人的报名记录（用户端权限，本需求管理端部分只关心行政视角）。
- 行政可以查看全部报名记录、执行签到/撤销签到/取消任意一条记录、手动新增代报名记录。

## 8. 校验规则

- 员工自主报名：联系电话必填且需符合手机号格式（11位数字），备注选填。
- 行政手动代报名：姓名必填，部门/头衔选填（留空展示为"—"）。
- 取消报名为不可逆操作，执行前需二次确认。

## 9. 页面与状态清单

| 页面 | 需要的状态 |
|---|---|
| 报名管理（统计 + 名单 + 手动添加表单） | normal / loading / empty(该活动尚无人报名) |

## 10. 验收标准

- AC-001：点击"签到"后状态变为"已签到"，"已签到"统计数字同步 +1；点击"撤销签到"反向操作，统计数字 -1。
- AC-002：点击"取消报名"需二次确认（原地展示确认提示，不依赖浏览器原生弹窗），确认后该记录从列表移除，"已报名"统计 -1，若取消时该记录为"已签到"状态，"已签到"统计也同步 -1。
- AC-003：手动添加代报名时，姓名为空点击提交被阻止；提交成功后新记录出现在列表最上方，"已报名"统计 +1，表单自动清空并收起。
- AC-004：员工在用户端提交报名成功后，该条记录应能在管理端报名名单中查询到（前后端数据一致，非两套独立数据）。

## 11. 已知缺口与非目标

| 缺口 | 谁来定 | 何时前定 |
|---|---|---|
| 是否需要"名额上限"及报满后的排队/候补机制 | 行政 | 开发排期前 |
| 签到方式是否需要支持现场扫码，而不仅是管理端手动点击 | 行政 | 开发排期前 |
| 报名截止时间与 `module-002-admin` 的"开始展示时间"机制是否需要打通（报名截止后表单变为只读或隐藏） | 行政 | 开发排期前 |
