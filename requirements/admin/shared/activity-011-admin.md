# 已发布活动的模块配置修改（activity-011-admin）

## 1. 概述

活动发布后，行政常常需要临时调整用户页面上显示的内容（例如让某个板块提前或推迟出现、停用一个板块、调整寄语墙的留言截止时间）。目前 `activity-001-admin` §7 规定已发布活动只能「下线」，一旦要调整就只能下线，而下线是终态（活动变为 `已结束` 且不可逆），代价过大。

本需求让行政在 `已发布` 状态下，**只修改活动的「模块配置」**，保存即生效、不走审批；其他内容型信息仍然锁定。`草稿` / `已驳回` 状态下的编辑能力不变（仍可改全部内容，见 `activity-001-admin`）。

**非目标**：
- 不放开已发布活动的标题、类型、布局模板、计划开始/结束时间、举办地点、预算、简介、封面图、附件、第三节点审批人的修改。
- 不改变「下线」的语义：下线后活动变为 `已结束`，仍是终态，不能重新上线，也不提供「复制为新活动」（保持现状，已与行政确认）。
- 不放开 `审批中`、`已结束` 状态下的模块配置修改。
- 不涉及挂载在 Celebration 上的「报名信息」「涂鸦展示」两类模块（它们本就不受活动生命周期限制，见 `celebration-007-admin` §7）。

## 2. 涉及角色

引用 [`ROLES.md`](../../shared/ROLES.md)：行政（修改）、员工 / 外部人士（只读用户页面，受配置结果影响，不参与本操作）。

## 3. 术语与模块归属

引用 [`GLOSSARY.md`](../../shared/GLOSSARY.md)：活动模块、开始展示时间、外部可见性、**模块配置**、**配置修改记录**（本需求新登记）。依赖 `activity-001-admin`（活动状态机）、`module-002-admin`（模块的配置项与校验规则）。

## 4. 使用场景

- 行政发现Celebrations需要在活动当天才揭晓，于是把它的开始展示时间改到活动当天；用户页面按新时间显示。
- 活动进行中，行政把寄语墙留言截止时间延后一天，让更多员工有时间留言。
- 行政发现Celebrations里的内容有误，临时停用该板块，修改完成后再重新启用；停用期间用户页面不显示，已填的内容不丢。
- 行政需要调整几个板块在页面上的先后顺序。
- 两位行政同时打开了同一个活动的模块配置，后保存的人需要知道别人已经改过。

## 5. 业务流程与状态机

### 5.1 活动状态机：无变化

本需求不新增、不改变活动状态，也不触发审批。`已发布` 状态下修改模块配置，保存后活动仍是 `已发布`。状态机见 `activity-001-admin` §5.1。

### 5.2 各状态下模块配置的可编辑性

| 活动状态 | 模块配置可否修改 | 说明 |
|---|---|---|
| `草稿` / `已驳回` | 可 | 随活动整体编辑（创建流程第二步），规则见 `module-002-admin` |
| `审批中` | 不可 | 随活动锁定 |
| `已发布` | **可（本需求）** | 只能改模块配置，保存即生效，不触发审批 |
| `已结束`（含已下线） | 不可 | 终态，只读 |

### 5.3 保存生效与用户端联动

- 保存成功后立即对用户页面生效：用户下次打开或刷新页面看到新配置。**不通知**正在浏览活动页的用户，也不通知已报名的员工（已确认）；不做主动推送、不发站内信或消息。
- **停用模块**：用户页面不再显示该板块；该模块已产生的数据（如寄语墙的留言、模块里已填的内容）**保留不删除**；重新启用后数据恢复显示。停用只影响用户页面的显示，**不影响管理端对已有数据的处理**：寄语墙停用后，行政仍可在寄语管理（`wall-005-admin`）里审核、隐藏、编辑历史留言；数据统计（`stats-006-admin`）继续计入该模块已有数据。
- **重新开放**：已过截止时间的模块，行政可以把截止时间改到未来（新值须晚于保存时刻，见 §8），模块随即按新时间重新进入对应阶段（如重新开放留言）。
- **启用模块**（此前未启用或曾停用）：按保存的配置显示，受其开始展示时间约束。
- **改开始展示时间 / 截止时间**：按 §8 的校验约束；改动后模块的阶段（未开始 / 提交中 / 已结束等）按新时间重新计算，规则见 `module-002-admin` §5.1。

### 5.4 并发修改

两位行政同时修改同一活动的模块配置时，以进入编辑页时看到的配置版本为准：保存时若发现该活动的模块配置在此期间已被他人修改，本次保存被拒绝并提示冲突，**不静默覆盖**；被拒绝的人需刷新、查看最新配置后重新修改。

## 6. 数据对象

**模块配置**：一个活动下全部「活动模块」的配置总和，即创建活动第二步里能设置的全部内容——各模块的启用与否、专属参数（如寄语墙的留言截止时间、内容型模块的内容）、通用配置（开始展示时间、模块排序）。不含布局模板，也不含 Celebration 上的模块。对象本身的定义见 `module-002-admin` §6，本需求不重新定义。

**配置修改记录**：`已发布` 状态下每一次成功保存的模块配置修改，留一条记录，内容为：谁（行政）、什么时间、改了哪些模块的哪些项、改前值与改后值。记录只增不改不删，用于审计追溯。被拒绝的保存（校验失败、冲突）不产生记录。记录显示在活动详情页的「修改记录」区块里，按修改时间倒序（最新在前），分页见 [`conventions.md`](../../../background/conventions.md)「分页」；没有任何记录时显示「暂无修改记录」。区块只读，不提供编辑或删除入口。

**配置版本**：模块配置每被成功保存一次即视为一个新版本，用于识别并发修改（§5.4）。这是业务语义概念，具体实现形式由接口清单定义。

## 7. 权限规则

- **任一行政**在活动处于 `已发布` 状态时，都可以修改该活动的模块配置，不限于活动发起人；操作入口在活动详情页。（草稿 / 已驳回状态的编辑仍按 `activity-001-admin` §7 限发起人，不受影响。）
- 活动详情页的「修改记录」区块：**发起人视角和只读访客视角显示；审批人视角（从统一待办跳转进入、当前用户是待处理节点审批人）不显示**。三种视角的定义见 `activity-001-admin` AC-008。员工、外部人士不进入管理端，不涉及。
- `已发布` 状态下，行政**不能**借此入口修改模块配置以外的任何内容（标题、时间、地点、预算、简介、封面图、附件、布局模板、第三节点审批人）；后端必须拒绝请求中夹带这些内容，不能只靠前端隐藏（见 §8）。
- `外部可见性` 仍按 `activity-001-admin` §7 的例外规则单独修改，与本需求互不影响，二者各自保存。
- 非行政角色（部门主管、审批人、员工、外部人士）没有该入口，后端同样拒绝。
- `草稿`、`已驳回`、`审批中`、`已结束` 状态下，没有「修改已发布活动模块配置」这一入口，后端同样拒绝。

## 8. 校验规则

- **状态校验**：保存时后端校验活动当前状态必须仍是 `已发布`。编辑期间活动被下线（变为 `已结束`）的，保存被拒绝并提示「活动已结束，无法修改」。
- **范围校验**：保存请求只能包含模块配置；夹带任何模块配置以外的内容，整个请求被拒绝。触发时机：每次保存，后端校验。
- **模块类型范围校验**：已发布后修改的 `modules` 只能包含挂载在活动上的两类模块（Celebrations、寄语墙）；出现已下线的类型（CEO 致辞、历史时间轴，见 `module-002-admin` §3 变更说明）、挂载在 Celebration 上的类型（报名信息、涂鸦展示）或其他任何类型，整个请求被拒绝，配置不变。触发时机：每次保存，后端校验。
- **沿用规则**：`module-002-admin` §8 的全部校验（留言截止时间晚于活动计划开始时间、开始展示时间不晚于该模块任何截止时间等）在发布后修改时同样适用。
- **截止时间不得早于当前时间**：把任一模块的截止时间（如留言截止时间）改成早于保存时刻的时间，被拒绝并提示原因。未改动的截止时间即使已经过去，保存时不受影响。
- **已开始展示的模块，开始展示时间不得改到未来**：模块的开始展示时间已到（用户页面已在显示它）时，不允许把开始展示时间改成晚于当前时间，被拒绝并提示原因（想收回请使用「停用」）。尚未开始展示的模块，开始展示时间可自由改（仍受沿用规则约束）。
- **并发校验**：保存时若模块配置版本已变化，拒绝并提示冲突（§5.4）。
- **留痕**：每次成功保存必须写入一条配置修改记录；记录写入失败时，本次保存整体失败，不允许配置已改而无记录。
- 以上校验均为前端提示 + 后端二次校验，不可仅信任前端。

## 9. 页面与状态清单

| 页面 | 需要的状态 |
|---|---|
| 活动详情页（所有状态）中的「修改记录」区块（只读列表，仅在有过已发布后修改时有内容） | normal / loading / empty(暂无修改记录) / error(记录加载失败，可重试) / overflow(单条记录改动项很多、值很长、记录条数多需分页时的展示) |
| 活动详情页（`已发布`）中的「编辑模块配置」入口 | normal（`已发布` 且为行政：显示入口）/ noperm（非行政：不显示入口）；`草稿`/`审批中`/`已结束` 状态不显示该入口 |
| 编辑模块配置页（复用创建活动第二步的模块配置界面，其余信息只读展示，或不展示） | normal / loading / error(校验不通过，含截止时间早于当前、开始展示时间改到未来) / error(保存失败，可重试) / error(版本冲突，提示刷新) / error(活动已不是已发布，无法保存) / noperm(无权限或状态不允许，直接访问时) / overflow(模块较多、模块里文本很长时的展示) |

「empty」不适用：两类活动模块是固定枚举，全部停用也只是各开关为关闭状态，不存在「没有数据」的页面形态。

## 10. 验收标准

- AC-001：活动状态为「已发布」时，行政在活动详情页看到「编辑模块配置」入口；状态为「草稿」「已驳回」「审批中」「已结束」时，详情页不显示该入口；活动列表操作列仍只有「查看详情」「下线」（与 `activity-001-admin` AC-005 一致，不新增入口）。
- AC-002：点击「编辑模块配置」后，只出现模块配置的内容（各模块启用开关、专属参数、开始展示时间、排序）；标题、时间、地点、预算、简介、封面图、附件、布局模板、第三节点审批人不可编辑。
- AC-003：修改模块配置并保存成功后，活动状态仍为「已发布」，不产生审批记录，不触发任何统一待办；用户页面按新配置显示。
- AC-004：已发布活动的模块配置保存请求中夹带标题、时间、地点、预算、简介、封面图、附件、布局模板或审批人等模块配置以外的内容时，后端拒绝整个请求（直接调接口也被拒绝，不依赖前端隐藏）。
- AC-005：活动状态不是「已发布」（含编辑期间被下线变为「已结束」）时，保存模块配置被后端拒绝，并提示「活动已结束，无法修改」或对应原因。
- AC-006：非行政角色看不到该入口，直接调用保存接口被后端拒绝。
- AC-007：停用一个已有数据的模块（如已有留言的寄语墙）后，用户页面不再显示该板块；该模块已产生的数据不被删除；重新启用后原数据恢复显示。
- AC-008：把任一模块的截止时间改成早于保存时刻的时间时，保存被阻止并提示原因；未修改的、已经过去的截止时间不受影响，其他项照常保存。
- AC-009：模块的开始展示时间已到（用户页面已在显示它）时，把开始展示时间改成晚于当前时间，保存被阻止并提示「请使用停用」类原因；尚未开始展示的模块可以修改开始展示时间。
- AC-010：已发布活动修改模块配置时，`module-002-admin` §8 的沿用校验仍生效（如留言截止时间必须晚于活动计划开始时间，开始展示时间不得晚于该模块任何截止时间）。
- AC-011：两位行政同时打开同一活动的模块配置，先保存者成功；后保存者被拒绝并提示「配置已被他人修改，请刷新后重试」，不静默覆盖；刷新后看到的是最新配置。
- AC-012：每次成功保存产生一条配置修改记录，包含操作行政、时间、改动的模块与项、改前值与改后值；校验失败或冲突导致的保存失败不产生记录；记录写入失败时本次保存整体失败，配置不变。
- AC-013：「外部可见性」的修改（`activity-001-admin` AC-007）与模块配置修改互相独立，各自保存，互不影响。
- AC-014：「草稿」「已驳回」状态下的编辑行为不变，模块配置仍随活动整体编辑，不受本需求影响。
- AC-015：任一行政（不限发起人）在「已发布」活动的详情页都能看到「编辑模块配置」入口并保存成功；非行政看不到。
- AC-016：活动详情页有「修改记录」区块（发起人视角和只读访客视角显示，审批人视角不显示，见 AC-021），按修改时间倒序列出每次已发布后的模块配置修改：操作行政、修改时间、改动的模块与项、改前值与改后值；区块只读，无编辑或删除入口；没有记录时显示「暂无修改记录」；记录加载失败时显示错误并可重试；记录多时按分页展示。
- AC-017：新保存成功的修改，刷新活动详情页后立即出现在「修改记录」顶部；保存失败（校验、冲突、状态不符）不新增记录。
- AC-018：活动下线变为「已结束」后，详情页仍显示全部历史修改记录，但不再有「编辑模块配置」入口。
- AC-019：已过截止时间的模块，行政把截止时间改成晚于保存时刻的时间后保存成功，模块按新截止时间重新进入对应阶段（如寄语墙重新开放留言）；改成不晚于保存时刻时被拒绝（见 AC-008）。
- AC-020：寄语墙被停用后，行政在寄语管理里仍能查看、审核、隐藏、编辑该活动的历史留言；用户页面不显示寄语墙；数据统计里该活动的寄语相关指标继续计入已有数据。
- AC-021：审批人从统一待办跳转进入活动详情页（审批人视角）时，不显示「修改记录」区块；同一活动由发起人或只读访客打开时显示。后端对审批人视角也不返回修改记录。
- AC-022：已发布活动的模块配置保存成功后，不向正在浏览活动页的用户或已报名的员工发送任何通知（无推送、无站内信、无消息）；用户只在下次打开或刷新页面时看到新配置。
- AC-023：已发布活动保存模块配置时，请求里只能包含Celebrations、寄语墙两类模块；带上 CEO 致辞、历史时间轴（已下线）、报名信息、涂鸦展示（挂载在 Celebration 上）或任何其他模块类型时，后端拒绝整个请求，模块配置不变。

**非目标补充**：已发布活动不能修改简介、封面图等基础信息（已确认，不再是缺口）；修改后不通知用户（已确认）。
