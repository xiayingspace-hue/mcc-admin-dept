# 员工身份识别与参与限制（identity-009-admin）

## 1. 概述

用户端活动页面有两类访问者：从公司内部系统进入的**员工**，和从公司官网进入的**外部人员**。报名、涂鸦投票、提交寄语这三个动作**只允许员工参与**；外部人员可以浏览，但没有这三个动作的入口：页面上这三个入口直接关闭（不显示），页面上也不需要任何说明（已确认，不再提示"可联系行政代报名 / 代留言"之类的文字）。

本需求定义三件事：如何识别访问者是不是员工、非员工能做什么不能做什么、页面上如何提示。

**非目标**：
- 不做外部人员的登录或注册（官网访问一律视为外部人员，没有升级为员工的途径）。
- 不做员工内部的分级（全员 / 指定部门），那是活动的"参与范围"，见 `activity-001-admin`，与本需求互相独立。
- 不改变外部人士的现有参与方式：报名、留言仍由行政代录入（见 `registration-004-admin`、`wall-005-admin`）。
- 不覆盖管理端（行政后台）的账号体系。

## 2. 涉及角色

引用 [`ROLES.md`](../../shared/ROLES.md)：员工、外部人士。

## 3. 术语与模块归属

本需求使用的术语见 [`GLOSSARY.md`](../../shared/GLOSSARY.md)：员工身份、内部访问令牌、参与入口关闭。

被本需求约束的动作分别归属：报名（`registration-004-admin`）、涂鸦投票（`submission-003-admin`）、提交寄语（`wall-005-admin`）。三份文档只引用本需求的规则，不各自重新定义。

## 4. 使用场景

- 员工在公司内部系统里点进活动页面，直接可以报名、投票、写寄语，不需要再登录。
- 外部人员通过公司官网打开同一个活动页面，可以浏览活动内容、作品和已展示的寄语，但页面上没有报名、投票、写寄语的入口。
- 员工在页面上停留较久，登录状态过期后再点击参与按钮，被提示重新登录。
- 已离职的员工，即使手里还有内部系统传来的令牌，也按外部人员处理：看不到入口，调用接口被拒绝。
- 有人绕过页面，直接调用接口冒充员工参与，被后端拒绝。

## 5. 业务流程与状态机

访问者身份由后端判定，页面只展示结果。访问者在页面上的身份状态：

| 状态 | 触发条件 | 页面表现 |
|---|---|---|
| `确认中` | 页面刚打开，正在向后端确认身份 | 三个参与入口暂不显示（确认为员工后才出现，外部人员始终看不到，不会闪现） |
| `员工` | 带着内部系统传来的有效令牌进入，且该员工在 HR 系统中的状态是在职（`on the job` 或 `probation`） | 参与入口按各自模块原有规则显示 |
| `外部人员` | 没有令牌（如从官网进入）、令牌无效，或令牌对应的员工在 HR 系统中不是在职状态 | 三个参与入口直接关闭，页面上看不到入口，也没有提示文字 |
| `登录已过期` | 之前确认为员工，之后令牌失效，在点击参与动作时被后端拒绝 | 提示"登录已过期，请重新登录" |
| `确认失败` | 确认身份的请求失败（网络、服务异常，或向 HR 系统查询在职状态时查不到 / 超时） | 参与入口不显示，在原入口位置显示一行"身份确认失败"并提供"重试" |

各状态下访问者不会自动变成另一种身份；`登录已过期`、`确认失败`的解决办法分别是重新登录、重试。

## 6. 数据对象

**访问者（Viewer）**：当前正在访问用户端页面的人。包含身份类型（员工 / 外部人员）；身份类型为员工时，另有该员工的唯一标识与姓名，由后端根据内部访问令牌得到。访问者不是需要存储的业务记录，每次访问由后端实时判定。

**内部访问令牌**：公司内部系统在员工跳转到活动页面时传递的凭证，用来证明访问者是员工。令牌里带的工号来自 HR 系统，不会重复；令牌的签发、校验、有效期由公司内部系统与后端约定（见 §11）。

## 7. 权限规则

| 动作 | 员工 | 外部人员 |
|---|---|---|
| 浏览活动页面、Celebration 详情、已发布的作品、已展示的寄语 | 可以 | 可以（受活动"外部可见性"限制，见 `activity-001-admin`） |
| 报名 / 取消自己的报名、查看自己的签到码 | 可以 | 不可以 |
| 涂鸦投票（含取消投票、换票） | 可以 | 不可以 |
| 提交寄语 | 可以 | 不可以 |

- 外部人士的报名、留言仍由行政在管理端代录入，不受本规则影响。
- 寄语墙模块原有的"允许外部人士留言"属性已取消（连同"展示样式"属性一并取消，见 `module-002-admin`）：外部人员在用户端一律不能提交寄语，外部人士的留言只能由行政代录入。
- 管理端行政账号的权限不受本需求影响。

## 8. 校验规则

- **身份以后端为准**：上表三类动作（报名、投票、提交寄语）的接口，后端必须根据服务端校验后的内部访问令牌判定身份；不得采信前端传来的工号、身份类型或"是否员工"之类的参数。该规则不依赖页面上入口是否显示。
- **在职状态以 HR 系统为准，每次请求实时查询**：令牌里的工号来自 HR 系统，不会重复。后端每次判定访问者身份、以及每次处理报名 / 投票 / 提交寄语请求时，都实时向 HR 系统查询该工号的状态，不使用缓存或定时同步的结果。状态为 `on the job`（在职）或 `probation`（试用期）的才是员工；其他任何状态（包括已离职）都按外部人员处理，即使令牌尚未过期。员工登录内部系统时已校验过在职状态，这里再核对一次是为了逻辑严密。HR 系统里状态何时变更，由 HR 流程决定，本系统只看查询时的当前状态。
- **非员工被拒**：外部人员（无令牌 / 令牌无效 / 在 HR 系统中不是在职状态）调用这些接口，被拒绝，不产生任何报名、投票或留言记录，并返回"不是员工"的明确原因。
- **令牌过期**：令牌过期或失效时同样被拒绝，并返回"登录已过期"的明确原因，与"不是员工"区分。
- **令牌不残留**：页面用令牌换取登录状态后，令牌不应继续停留在浏览器地址栏里（避免被复制、分享或进入浏览记录）。
- **身份确认失败时不放开**：页面确认身份的请求失败时，按"不可用"处理，不得默认放开参与。后端向 HR 系统查询在职状态时查不到或超时，同样按"拒绝"处理，不放行，也不把访问者当作外部人员或员工中的任何一种，而是返回"身份确认失败"（与"不是员工"区分）；报名 / 投票 / 提交寄语请求因此被拒绝时，页面提示"身份确认失败，请稍后重试"，不产生任何记录。
- 页面上入口的显示与关闭只是体验层，不能替代以上后端校验。

## 9. 页面与状态清单

本需求不新增页面，只给已有的三个参与入口增加身份维度的状态：

| 入口（页面） | 需要的状态 |
|---|---|
| 报名入口（Celebration 详情页右侧「Event Details」卡片的「立即报名」按钮） | normal(员工) / loading(确认身份中：不显示) / noperm(外部人员：不显示，卡片其余内容照常) / noperm(登录已过期：入口仍显示，点击后提示) / error(确认失败：入口位置一行提示与重试) |
| 涂鸦投票（Celebration 详情页涂鸦展示区；活动作品展示页） | normal(员工) / loading(不显示投票按钮) / noperm(外部人员：不显示投票按钮，作品卡片与票数照常显示) / noperm(登录已过期) / error(区域标题下一行提示与重试) |
| 提交寄语（活动详情页寄语墙板块「写下你的寄语」按钮） | normal(员工) / loading(不显示) / noperm(外部人员：不显示，已展示的寄语照常) / noperm(登录已过期) / error(入口位置一行提示与重试) |

页面表现规则：
- 外部人员状态下，三个入口整个不显示：报名按钮、投票按钮、「写下你的寄语」按钮都不出现，不留置灰按钮，也没有"仅限员工"之类的提示文字。所在板块（Event Details 卡片、涂鸦作品、寄语墙）本身照常显示。
- 与其他状态同时成立时的优先级：①模块的展示开关关闭 → 整块不显示、没有入口；②访问者不是员工 → 入口关闭（不显示）；③其他状态（已报名、名额已满、留言或投票已截止等）沿用各模块原有规则。因此外部人员看不到报名入口，也就不会看到"报名人数已达上限"。
- 外部人员浏览涂鸦作品、寄语墙、作品详情不受影响。

## 10. 验收标准

- AC-001：员工带着有效的内部访问令牌进入活动页面后，报名、涂鸦投票、提交寄语三个入口按各自模块的原有规则显示与使用，不需要再次登录。
- AC-002：外部人员（无令牌 / 令牌无效 / 令牌对应的员工已离职，包括从公司官网进入）打开页面后，报名、涂鸦投票、提交寄语三个入口直接关闭：报名按钮、各作品的投票按钮、「写下你的寄语」按钮都不显示，也没有"仅限员工"之类的提示文字；Event Details 卡片、涂鸦作品与票数、寄语墙已展示的留言照常显示。
- AC-003：外部人员的页面上没有任何可点击的参与入口（不弹报名弹窗、寄语弹窗，不产生投票）；同一个页面里，员工看到的入口和使用方式不受影响。
- AC-004：外部人员仍可浏览活动内容、Celebration 详情、已发布的作品与票数、已展示的寄语，不受影响。
- AC-005：外部人员绕过页面，直接调用报名、投票、提交寄语的接口，被后端拒绝并返回"不是员工"的明确原因，不产生任何记录。
- AC-006：后端判定身份只依据服务端校验后的内部访问令牌；请求里带了员工工号、"是否员工"等参数但没有有效令牌的，同样被拒绝。
- AC-007：令牌过期或失效后，员工再点击参与动作，被拒绝并提示"登录已过期，请重新登录"；该提示与"仅限员工参与"不同，不让员工误以为自己不是员工。
- AC-008：页面用令牌换取登录状态后，令牌不再出现在浏览器地址栏中。
- AC-009：页面确认身份期间，三个入口暂不显示（确认为员工后才出现）；确认身份失败（含后端向 HR 系统查询超时 / 查不到）时，入口仍不显示，在原入口位置（涂鸦展示区在区域标题下）显示一行"身份确认失败"与"重试"，点击重试重新确认；失败时不得默认放开参与，也不显示成外部人员。
- AC-010：模块展示开关关闭时，该模块整块不显示、没有入口，不论访问者身份；展示开关打开且访问者为外部人员时，入口同样不显示（因此外部人员不会看到"报名人数已达上限"）。
- AC-011：行政在管理端为外部人士代报名、代录入寄语不受本规则影响，照常可用。
- AC-012：在 HR 系统中状态不是在职（`on the job`、`probation` 之外，包括已离职）的人按外部人员处理：即使带着尚未过期的内部系统令牌进入，页面上也没有报名、投票、提交寄语的入口；直接调用这三类接口被后端拒绝并返回"不是员工"（`not_employee`），不产生任何记录。状态为 `on the job` 或 `probation` 的员工不受影响，都视为员工。
- AC-013：在职状态每次请求都实时向 HR 系统查询：员工在 HR 系统中状态变为非在职后，其下一次请求（打开页面、报名、投票、提交寄语）即按外部人员处理，不需要等令牌过期，也不受缓存影响；状态变回在职后，下一次请求即恢复为员工。
- AC-014：后端向 HR 系统查询在职状态时查不到或超时：打开页面的身份确认显示"身份确认失败"与"重试"（AC-009）；直接调用报名、投票、提交寄语接口被后端拒绝并返回"身份确认失败"（`identity_unavailable`，与 `not_employee` 区分），页面提示"身份确认失败，请稍后重试"，不产生任何记录；任何情况下都不因查询失败而放行。

## 11. 已知缺口与非目标

| 缺口 | 谁来定 | 何时前定 |
|---|---|---|
| 内部访问令牌的具体机制：是否一次性、有效期多长、页面用令牌换取登录状态的方式、令牌如何校验（验签 / 向内部系统确认） | 开发 + 内部系统负责人 | 开发排期前 |
| 用户端员工自主报名、投票、提交寄语的接口目前都不在接口清单里，补充时必须带上本需求 §8 的身份校验 | 开发 | 补接口清单时 |
