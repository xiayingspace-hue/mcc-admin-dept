# 活动创建、审批与生命周期（activity-001-admin）

## 1. 概述

行政创建一场公司活动（周年庆/年会/团建/生日会/培训分享会等）的基础信息，经过审批链后发布，活动经历完整生命周期直到结束或下线。本需求覆盖活动主体本身的数据、状态机、审批流程；不覆盖活动内部具体"玩法"（见 `module-002-admin`）。活动的举办时间/地点为本对象自身字段，与其下属各 Celebration（分站点子活动，见 `celebration-007-admin`）各自独立的举办时间/地点互不覆盖、互不派生。自 REQ-007/REQ-008 起，用户端活动详情页新增"Celebrations"区块（见 `celebration-007-admin`）与"Become a Sponsor"入口（见 `sponsor-008-admin`），两者均为独立需求文档定义的内容，本文档不重复描述。

**非目标**：不做自由拖拽页面搭建；不做独立"审批中心"（审批待办复用公司统一待办列表，本需求只提供被跳转的详情落地页）。

## 2. 涉及角色

引用 [`ROLES.md`](../../shared/ROLES.md)：行政（发起/编辑/查看）、部门主管（审批节点1）、第三节点审批人（审批节点2，由发起人在步骤三从全公司员工中自选，可多人与签）。

## 3. 术语与模块归属

引用 [`GLOSSARY.md`](../../shared/GLOSSARY.md)：布局模板、外部可见性、参与范围、审批进度页。

## 4. 使用场景

- 行政策划一场周年庆，创建活动、选布局模板、配置基础信息，并在步骤三按业务需要挑选哪些人在第三节点一起签字，然后提交审批。
- 部门主管、第三节点审批人在公司统一待办列表里收到审批任务，处理后活动自动流转；第三节点全部通过后活动自动发布。
- 行政在活动列表里查看所有活动的状态，对已发布活动执行下线，对草稿/被驳回活动继续编辑。
- 活动结束后，行政需要单独调整"外部可见性"（无需重新走审批）。

## 5. 业务流程与状态机

### 5.1 活动状态机

| 当前状态 | 触发动作 | 下一状态 |
|---|---|---|
| （新建）| 保存草稿 | `草稿` |
| `草稿` | 提交审批 | `审批中` |
| `审批中` | 审批链全部节点通过（见 §5.2，最后一个节点通过即自动流转，无需任何人再操作） | `已发布` |
| `审批中` | 任一节点中任一审批人驳回 | `已驳回` |
| `已驳回` | 修改后重新提交 | `审批中` |
| `审批中` | 发起人点击"撤回申请" | `草稿` |
| `已发布` | 行政点击"下线" | `已结束` |
| `已发布` / `已结束` | — | 终态，`已结束`后不可再逆转为其他状态（外部可见性调整除外，见 §7） |

### 5.2 审批链（固定三个节点，其中第三节点的审批人由发起人自选）

```
节点1 提交（发起人） → 节点2 部门主管审批 → 节点3 第三节点审批（多人并行与签） → 自动发布
```

- 节点1「提交」不是审批动作，记录发起人与提交时间，目的是让审批人在详情页看到完整的流程节点；节点2、节点3 是审批节点。
- 审批链与预算金额无关，不再有金额阈值，也不再有"行政初审""财务审批""行政终审并发布"节点。预算仅作为活动基础信息保留（见 §8）。
- **节点2 部门主管**：发起人所属部门的负责人，由系统按发起人自动匹配，发起人不能指定。
- **节点3 第三节点审批人**：由发起人在步骤三从全公司员工中任选，人数不设上限，必选，至少选 1 人，不允许跳过该节点（见 §8）；发起人本人可被选中；同一人不能重复选；所选的人与节点2 的部门主管是同一人时，两个节点各自独立处理一次。
- **节点3 的与签规则**：所选审批人并行处理，不分先后；全部通过，节点3 才算通过，随即活动状态自动变为 `已发布`；其中任一人驳回，活动整体退回 `已驳回`，其余尚未处理的审批人的统一待办任务同步撤销，这些人此后不能再对该次提交执行通过/驳回。
- 节点3 的统一待办在节点2 通过后才同时发给全部所选审批人；节点2 通过前，所选审批人收不到待办。
- 任一节点驳回，活动整体退回 `已驳回`，不保留已通过节点的状态（重新提交需从头走审批链）。这是当前版本的简化实现；"驳回后是否需要重走已通过节点"留作已知缺口。
- 驳回或撤回后重新提交时，发起人可重新选择第三节点审批人；`审批中` 状态下不能增加或减少第三节点审批人。

### 5.3 发起人撤回申请

- 活动处于 `审批中` 状态时，发起人可在任意阶段撤回申请，不论当前审批链已有多少节点通过、不受审批进度限制。
- 撤回后活动状态直接回到 `草稿`（不经过 `已驳回`）；与驳回一致，不保留已通过节点的记录，重新提交需从审批链第一个节点重新走完整流程。
- 撤回时，当前审批节点对应的"统一待办列表"任务中所有尚未被处理的都需联动撤销；节点3 有多位审批人时，指所有尚未处理的审批人的待办任务，已处理的人及已处理完的节点不存在待处理任务，不受影响。待办任务撤销的具体实现由统一待办系统承接，本需求只定义"活动被撤回时触发撤销"这个动作本身，不重复实现待办系统的能力（见 §1 非目标）。

## 6. 数据对象

**活动（Activity）**：一场公司活动的主体。包含活动的基础事实（标题、类型、时间、地点、预算、简介）、生命周期状态、审批关联、页面呈现相关的两个独立属性——参与范围（内部谁能报名，属 `registration` 数据范畴的边界设定）与外部可见性（页面是否允许内部之外的人访问）、布局模板（决定详情页整体骨架，取值来自开发维护的有限枚举）。

**审批实例（ApprovalInstance）**：一个活动对应一条审批流程实例，记录当前处于哪个节点。

**审批节点记录（ApprovalStep）**：审批链上每一个节点（提交、部门主管审批、第三节点审批）的状态与时间戳，供发起人和审批人双视角查看；每个节点下挂一条或多条审批人记录，节点3 因多人与签而挂多条，每条记录各自的审批人、结果、意见、处理时间。节点1「提交」下只有发起人一条记录，无审批结果。

## 7. 权限规则

- 只有活动的发起人（创建者）可以编辑处于 `草稿` / `已驳回` 状态的活动；处于 `审批中` 状态时，发起人可在任意阶段撤回申请，不受当前审批进度限制，具体状态流转与联动效果见 §5.3。
- 只有当前审批节点对应的审批人可以对该节点执行"通过/驳回"，且必须填写驳回意见（通过意见选填）。节点3 的每位审批人只能处理属于自己的那一条，不能代他人处理。
- 第三节点审批人只有发起人能选择，且仅在 `草稿` / `已驳回` 状态（含撤回后回到的 `草稿`）下可修改；`审批中` 状态下任何人都不能增减，包括发起人。
- `已发布` 状态的活动，行政只能执行"下线"，不能编辑内容型字段（标题/时间/地点/预算/简介）；这是当前版本的限制，若业务需要"发布后仍可编辑非审批相关字段（如简介、封面图）"，属已知缺口，需与行政确认。
- **"外部可见性"是唯一的例外**：`已发布` 或 `已结束` 状态下，行政可以直接修改此字段，不触发审批流程、不改变活动主状态。
- `草稿` 状态的活动，发起人可直接硬删除；`已发布`/`已结束`/`已驳回` 状态不提供删除，只提供状态转移。

## 8. 校验规则

- 创建/编辑时必填：活动标题、活动类型、布局模板、开始时间、结束时间、举办地点、预算。选填：封面图、活动简介（富文本）。
- 结束时间必须晚于开始时间，独立于"是否为空"校验单独提示。
- 预算为非负数字。
- 提交审批前，以上必填项校验必须全部通过，前端拦截 + 后端二次校验（不可仅信任前端）。
- 提交审批前，第三节点审批人至少选择 1 人；同一人不能重复选；所选人必须是全公司员工范围内的有效账号，同样前端拦截 + 后端二次校验。人数无上限。
- 预算金额不参与审批链匹配，不因金额大小而增加、减少或跳过审批节点。
- 审批驳回时，驳回意见为必填项。
- 节点3 中已有人驳回后，其余审批人再提交"通过/驳回"必须被拒绝（后端校验，不依赖前端隐藏入口），避免并发下已驳回的活动被重复处理。
- 撤回申请为不可逆操作（清空已有审批进度），执行前需二次确认。

## 9. 页面与状态清单

| 页面 | 需要的状态 |
|---|---|
| 活动列表 | normal / loading / empty(从未创建过活动) / empty(筛选无结果) / error / noperm(非本人创建的草稿不可见编辑入口) |
| 创建活动 - 基础信息（步骤一） | normal / error(字段校验失败) |
| 创建活动 - 配置模块（步骤二） | normal（依赖 `module-002-admin`） |
| 提交审批（步骤三，含信息确认与第三节点选人，不含审批链节点预览） | normal / loading(员工列表加载中) / empty(员工搜索无结果) / empty(尚未选择第三节点审批人) / error(必填项缺失或未选第三节点审批人，阻止提交) / error(员工列表加载失败) / overflow(已选审批人数很多时的展示) |
| 审批进度 / 活动详情页（固定显示三个节点：提交、部门主管审批、第三节点审批） | normal(发起人视角) / normal(审批人视角，来自统一待办跳转) / loading / error(审批进度加载失败) / overflow(第三节点审批人很多时的展示) |

步骤三的员工选择器面向全公司员工，不按角色过滤，因此 noperm 不适用；审批进度页没有"无权限"独立形态，非发起人且非审批人访问时按 `viewer_role=viewer` 只读展示，见 AC-008。

## 10. 验收标准

- AC-001：创建活动时，活动标题/类型/布局模板/开始时间/结束时间/举办地点/预算为必填，未填写并点击"下一步"时对应字段高亮并显示错误提示，且不进入下一步。
- AC-002：结束时间早于或等于开始时间时，即使两个字段都非空，也会单独报错"结束时间需晚于开始时间"。
- AC-003：【已废止，编号留空不复用】原"预算超过阈值自动加入财务审批"规则已取消，审批链不再随预算变化，由 AC-011～AC-016 取代。
- AC-004：审批链任一节点的任一审批人点击"驳回"时，若未填写驳回意见，阻止提交；活动状态变为"已驳回"后，发起人可编辑并重新提交，审批链从第一个节点重新走，且步骤三可重新选择第三节点审批人（见 AC-016）。
- AC-005：活动状态为"已发布"时，活动列表操作列只提供"查看详情"和"下线"，不提供"编辑"。
- AC-006：活动状态为"草稿"时，操作列提供"编辑"和"删除"；点击删除需二次确认，确认后该活动记录从列表移除。
- AC-007：活动状态为"已发布"或"已结束"时，活动详情页的"外部可见性"字段旁显示"修改"入口；其他状态不显示该入口。点击修改、切换选项并保存后，字段值立即更新，不产生新的审批记录、不改变活动主状态。
- AC-008：同一个活动详情页，由"活动管理"列表进入时展示发起人视角操作（撤回申请），由统一待办列表跳转进入且当前用户是待处理节点的审批人时，展示审批人视角操作（通过/驳回 + 意见输入框）。
- AC-009：活动处于"审批中"状态时，发起人点击"撤回申请"需二次确认；确认后活动状态变为"草稿"，已通过节点的记录不保留，重新提交后审批链从第一个节点重新开始。
- AC-010：撤回申请后，当前审批节点对应的统一待办任务中所有尚未被处理的，在统一待办列表中同步被撤销（第三节点有多位审批人时，撤销所有尚未处理者的任务）；已处理完的节点或已处理的审批人本身没有待处理任务，不受影响。
- AC-011：创建活动的步骤三提供"第三节点审批人"选择，可从全公司员工中任选，人数不设上限，同一人不能重复选，发起人本人可被选中；选人时每位员工同时展示姓名和工号，用于区分重名，不展示部门；一个都没选就点击"提交审批"时，阻止提交并提示需至少选择 1 位第三节点审批人。步骤三只提供选人，不展示审批链节点预览；审批链的三个节点仅在提交后的审批进度/活动详情页展示（见 AC-012）。
- AC-012：活动提交审批后，审批进度/活动详情页固定显示三个节点：提交（发起人）、部门主管审批、第三节点审批；第三节点展示全部所选审批人及各自的处理状态。发起人视角与审批人视角看到的节点一致。
- AC-013：部门主管通过之前，所选第三节点审批人在统一待办列表中收不到该活动的任务；部门主管通过后，全部第三节点审批人同时收到待办，且并行处理、不分先后。
- AC-014：第三节点全部审批人均点击"通过"后，活动状态自动变为"已发布"，无需任何人再执行发布操作。只要还有一人未处理，活动保持"审批中"。
- AC-015：第三节点任一审批人点击"驳回"（必须填写驳回意见）后，活动状态变为"已驳回"；其余尚未处理的审批人的统一待办任务同步被撤销，这些人此后无法再对该次提交执行通过/驳回。
- AC-016：活动被驳回或被撤回后，发起人重新提交时步骤三可重新选择第三节点审批人；活动处于"审批中"状态时，详情页不提供增减第三节点审批人的入口，后端也拒绝此类修改。

## 11. 已知缺口与非目标

| 缺口 | 谁来定 | 何时前定 |
|---|---|---|
| 驳回后是否需要保留已通过节点的状态，而不是整体重新走审批链 | 行政 + 审批链涉及部门 | 开发排期前 |
| "已发布"活动是否允许编辑非审批相关字段（简介、封面图） | 行政 | 开发排期前 |
| 活动结束后修改"外部可见性"是否需要留痕（操作日志） | 行政 + 合规 | 开发排期前 |
| 活动的"外部可见性=对外开放"与模块级"允许外部人士留言/提交"开关之间的强制联动校验，是否要在活动状态变化时自动级联更新模块配置 | 行政 | 开发排期前，见 `module-002-admin` §11 |
| 第三节点某位审批人离职、转岗或账号失效时，该人的待办如何处理（转交他人 / 从审批人中移除 / 阻塞等待） | 行政 + HR | 开发排期前 |
| 发起人本人就是所属部门负责人（无上级可审）时，节点2 部门主管如何匹配 | 行政 | 开发排期前 |
| §5.3/AC-009 定义的"审批中任意阶段均可撤回申请"尚未完整实现，当前仅支持在审批链第一个节点通过前撤回；已通过节点后再撤回的路径待开发补齐 | 开发 | 待补齐后从本表移除，补齐前不视为已满足 AC-009/AC-020 |
