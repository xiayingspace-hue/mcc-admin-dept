# 活动创建、审批与生命周期（activity-001-admin）

## 1. 概述

行政创建一场公司活动（周年庆/年会/团建/生日会/培训分享会等）的基础信息，经过审批链后发布，活动经历完整生命周期直到结束或下线。本需求覆盖活动主体本身的数据、状态机、审批流程；不覆盖活动内部具体"玩法"（见 `module-002-admin`）。

**非目标**：不做自由拖拽页面搭建；不做独立"审批中心"（审批待办复用公司统一待办列表，本需求只提供被跳转的详情落地页）。

## 2. 涉及角色

引用 [`ROLES.md`](../../shared/ROLES.md)：行政（发起/编辑/查看）、部门主管（审批节点1）、财务（审批条件节点）。

## 3. 术语与模块归属

引用 [`GLOSSARY.md`](../../shared/GLOSSARY.md)：布局模板、外部可见性、参与范围、审批进度页。

## 4. 使用场景

- 行政策划一场周年庆，创建活动、选布局模板、配置基础信息，提交审批。
- 部门主管/财务在公司统一待办列表里收到审批任务，处理后活动自动流转。
- 行政在活动列表里查看所有活动的状态，对已发布活动执行下线，对草稿/被驳回活动继续编辑。
- 活动结束后，行政需要单独调整"外部可见性"（无需重新走审批）。

## 5. 业务流程与状态机

### 5.1 活动状态机

| 当前状态 | 触发动作 | 下一状态 |
|---|---|---|
| （新建）| 保存草稿 | `草稿` |
| `草稿` | 提交审批 | `审批中` |
| `审批中` | 审批链全部节点通过 | `已发布` |
| `审批中` | 任一节点驳回 | `已驳回` |
| `已驳回` | 修改后重新提交 | `审批中` |
| `审批中` | 发起人点击"撤回申请" | `草稿` |
| `已发布` | 行政点击"下线" | `已结束` |
| `已发布` / `已结束` | — | 终态，`已结束`后不可再逆转为其他状态（外部可见性调整除外，见 §7） |

### 5.2 审批链（按活动类型与预算自动匹配，行政不能手动指定审批人）

```
提交 → 部门主管审批 → 行政初审 → [预算 > 阈值？→ 财务审批] → 行政终审并发布
```

- 审批阈值：预算超过 ¥50,000 时，财务审批节点自动加入；否则跳过。阈值具体数值属于业务参数，非本需求锁定的常量，实现时读配置。
- 任一节点驳回，活动整体退回 `已驳回`，不保留已通过节点的状态（重新提交需从头走审批链）。这是当前版本的简化实现；"驳回后是否需要重走已通过节点"留作已知缺口。

### 5.3 发起人撤回申请

- 活动处于 `审批中` 状态时，发起人可在任意阶段撤回申请，不论当前审批链已有多少节点通过、不受审批进度限制。
- 撤回后活动状态直接回到 `草稿`（不经过 `已驳回`）；与驳回一致，不保留已通过节点的记录，重新提交需从审批链第一个节点重新走完整流程。
- 撤回时，若当前审批节点对应的"统一待办列表"任务尚未被处理，需联动撤销该待办任务；已处理过的节点本身不存在待处理任务，不受影响。待办任务撤销的具体实现由统一待办系统承接，本需求只定义"活动被撤回时触发撤销"这个动作本身，不重复实现待办系统的能力（见 §1 非目标）。

## 6. 数据对象

**活动（Activity）**：一场公司活动的主体。包含活动的基础事实（标题、类型、时间、地点、预算、简介）、生命周期状态、审批关联、页面呈现相关的两个独立属性——参与范围（内部谁能报名，属 `registration` 数据范畴的边界设定）与外部可见性（页面是否允许内部之外的人访问）、布局模板（决定详情页整体骨架，取值来自开发维护的有限枚举）。

**审批实例（ApprovalInstance）**：一个活动对应一条审批流程实例，记录当前处于哪个节点。

**审批节点记录（ApprovalStep）**：审批链上每一步的审批人、结果、意见、时间戳，供发起人和审批人双视角查看。

## 7. 权限规则

- 只有活动的发起人（创建者）可以编辑处于 `草稿` / `已驳回` 状态的活动；处于 `审批中` 状态时，发起人可在任意阶段撤回申请，不受当前审批进度限制，具体状态流转与联动效果见 §5.3。
- 只有当前审批节点对应的审批人可以对该节点执行"通过/驳回"，且必须填写驳回意见（通过意见选填）。
- `已发布` 状态的活动，行政只能执行"下线"，不能编辑内容型字段（标题/时间/地点/预算/简介）；这是当前版本的限制，若业务需要"发布后仍可编辑非审批相关字段（如简介、封面图）"，属已知缺口，需与行政确认。
- **"外部可见性"是唯一的例外**：`已发布` 或 `已结束` 状态下，行政可以直接修改此字段，不触发审批流程、不改变活动主状态。
- `草稿` 状态的活动，发起人可直接硬删除；`已发布`/`已结束`/`已驳回` 状态不提供删除，只提供状态转移。

## 8. 校验规则

- 创建/编辑时必填：活动标题、活动类型、布局模板、开始时间、结束时间、举办地点、预算。选填：封面图、活动简介（富文本）。
- 结束时间必须晚于开始时间，独立于"是否为空"校验单独提示。
- 预算为非负数字。
- 提交审批前，以上必填项校验必须全部通过，前端拦截 + 后端二次校验（不可仅信任前端）。
- 审批驳回时，驳回意见为必填项。
- 撤回申请为不可逆操作（清空已有审批进度），执行前需二次确认。

## 9. 页面与状态清单

| 页面 | 需要的状态 |
|---|---|
| 活动列表 | normal / loading / empty(从未创建过活动) / empty(筛选无结果) / error / noperm(非本人创建的草稿不可见编辑入口) |
| 创建活动 - 基础信息（步骤一） | normal / error(字段校验失败) |
| 创建活动 - 配置模块（步骤二） | normal（依赖 `module-002-admin`） |
| 提交审批（步骤三，含信息确认） | normal / error(必填项缺失阻止提交) |
| 审批进度 / 活动详情页 | normal(发起人视角) / normal(审批人视角，来自统一待办跳转) / loading |

## 10. 验收标准

- AC-001：创建活动时，活动标题/类型/布局模板/开始时间/结束时间/举办地点/预算为必填，未填写并点击"下一步"时对应字段高亮并显示错误提示，且不进入下一步。
- AC-002：结束时间早于或等于开始时间时，即使两个字段都非空，也会单独报错"结束时间需晚于开始时间"。
- AC-003：预算超过 ¥50,000 提交审批时，审批链自动包含"财务审批"节点；预算未超过阈值时不包含该节点，且该节点在审批进度页不显示。
- AC-004：审批链任一节点点击"驳回"时，若未填写驳回意见，阻止提交；活动状态变为"已驳回"后，发起人可编辑并重新提交，审批链从第一个节点重新走。
- AC-005：活动状态为"已发布"时，活动列表操作列只提供"查看详情"和"下线"，不提供"编辑"。
- AC-006：活动状态为"草稿"时，操作列提供"编辑"和"删除"；点击删除需二次确认，确认后该活动记录从列表移除。
- AC-007：活动状态为"已发布"或"已结束"时，活动详情页的"外部可见性"字段旁显示"修改"入口；其他状态不显示该入口。点击修改、切换选项并保存后，字段值立即更新，不产生新的审批记录、不改变活动主状态。
- AC-008：同一个活动详情页，由"活动管理"列表进入时展示发起人视角操作（撤回申请），由统一待办列表跳转进入且当前用户是待处理节点的审批人时，展示审批人视角操作（通过/驳回 + 意见输入框）。
- AC-009：活动处于"审批中"状态时，发起人点击"撤回申请"需二次确认；确认后活动状态变为"草稿"，已通过节点的记录不保留，重新提交后审批链从第一个节点重新开始。
- AC-010：撤回申请后，若当前审批节点对应的统一待办任务尚未被处理，该任务在统一待办列表中同步被撤销；已处理完的节点本身没有待处理任务，不受影响。

## 11. 已知缺口与非目标

| 缺口 | 谁来定 | 何时前定 |
|---|---|---|
| 驳回后是否需要保留已通过节点的状态，而不是整体重新走审批链 | 行政 + 审批链涉及部门 | 开发排期前 |
| "已发布"活动是否允许编辑非审批相关字段（简介、封面图） | 行政 | 开发排期前 |
| 活动结束后修改"外部可见性"是否需要留痕（操作日志） | 行政 + 合规 | 开发排期前 |
| 活动的"外部可见性=对外开放"与模块级"允许外部人士留言/提交"开关之间的强制联动校验，是否要在活动状态变化时自动级联更新模块配置 | 行政 | 开发排期前，见 `module-002-admin` §11 |
