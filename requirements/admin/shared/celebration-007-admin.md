# 活动 Celebration 管理（celebration-007-admin）

## 1. 概述

一个活动（如"公司30周年庆典"）可以在多个 site（地点）分别举办庆祝活动，例如新加坡总部站、北京分公司站、上海分公司站。"Celebration"是这类分站点子活动的载体：归属某个活动，拥有自己独立的举办时间、封面图、文字描述、图片相册，并可挂载"报名信息""涂鸦展示"两类模块（复用 `module-002-admin` 定义的模块类型概念，但挂载对象从"活动"改为"本 Celebration"）。一个活动下可以创建数量不限的 Celebration，也可以只创建一个（如团建类活动通常只有一个 site）。

Celebration 不参与活动审批流程：只要活动已存在，行政可随时创建、编辑该活动下的 Celebration，创建/编辑操作立即生效，不产生审批记录。

**非目标**：Celebration 不能脱离活动独立存在；Celebration 本身不提供布局模板选择（页面骨架统一由本文档定义，不可自定义）；不支持行政自定义新的挂载模块类型（与 `module-002-admin` 一致）。

## 2. 涉及角色

引用 [`ROLES.md`](../../shared/ROLES.md)：行政（创建/编辑本对象及其挂载模块）、员工/外部人士（浏览 Celebration 详情、报名、涂鸦投票，用户端行为）。

## 3. 术语与模块归属

引用 [`GLOSSARY.md`](../../shared/GLOSSARY.md)：Celebration、Site、CelebrationModule。依赖 `activity-001-admin`（活动必须先存在）。"报名信息""涂鸦展示"两类模块的类型定义、模块库展示仍由 `module-002-admin` 统一维护，本文档只定义这两类模块挂载在 Celebration 上时的专属规则（见 §5、§6、§8），`module-002-admin` 不再承载这两类模块（见该文档 §11 变更说明）。`registration-004-admin`、`submission-003-admin` 依赖本文档（报名记录、作品分别归属某个 Celebration 挂载的模块，不再直接归属活动）。

## 4. 使用场景

- 行政为"公司30周年庆典"活动分别在新加坡总部、北京分公司、上海分公司创建三个 Celebration，各自设置举办时间、封面图和现场相册。
- 行政为"Q3部门团建"活动只创建一个 Celebration（团建营地站）。
- 行政希望某个 Celebration 在举办之前，页面封面展示预告物料；举办当天及之后自动切换为现场实拍照片。
- 员工打开活动详情页，看到该活动下所有 Celebration 的卡片列表，点击进入某个具体 site 的页面报名或给涂鸦作品投票。
- 行政按活动、按状态（已举办 / 即将开始）筛选查看名下全部 Celebration 的情况。

## 5. 业务流程与状态机

### 5.1 Celebration 本身无审批流程

Celebration 的创建、编辑、（若支持）删除都是行政的直接操作，不触发活动审批链，不产生审批记录，操作后立即生效。

### 5.2 封面图展示状态（按时间自动判定）

```
当前时间 < Celebration 开始时间   → 展示"预告封面"
当前时间 ≥ Celebration 开始时间   → 展示"实拍封面"（若尚未上传实拍封面，继续展示预告封面，见 §11 已知缺口）
```

预告封面为必填项，实拍封面为选填项，由行政在举办前后自行上传/替换，系统不做人工审核。

### 5.3 挂载模块的展示与阶段状态

"报名信息""涂鸦展示"两类模块挂载在 Celebration 上后，其展示与阶段状态规则与 `module-002-admin` §5.1 定义的通用规则一致（开始展示时间 → 提交中/投票中 → 已结束的时间戳判断），仅挂载对象从"活动"改为"本 Celebration"。涂鸦展示模块沿用 `module-002-admin` §5.2 "作品来源为行政上传"的产品决策。

## 6. 数据对象

**Celebration**：归属某个活动的一条 site 级子活动记录。包含：所属活动（关联，只读）、Site/地点名称、Celebration 标题（独立于活动标题，允许与活动标题相同或不同）、Category（标记类型，如里程碑庆典、团建等，用于用户端展示分类徽章）、开始时间、结束时间、封面图（预告版必填、实拍版选填，展示规则见 §5.2）、文字描述（富文本）、图片相册（多张图片，与封面图分开维护，供员工浏览现场照片，不用于投票）、Highlights（自由文本多行列表，展示当天的活动看点，见 §11 是否需要收敛为结构化字段）。

**CelebrationModule**：某个 Celebration 启用的"报名信息"或"涂鸦展示"模块实例。字段与状态机复用 `module-002-admin` 对应模块类型的定义（含各自的开始展示时间、提交/投票截止时间等专属配置），仅挂载对象从"活动"改为"本 Celebration"。同一活动下不同 Celebration 各自的报名记录、作品与投票相互独立统计，互不影响，互不共享名额或数据。

## 7. 权限规则

- 仅行政可以创建、编辑该活动下的 Celebration 及其挂载模块配置；操作不依赖活动自身的生命周期状态（见 §11 已知缺口：活动处于"审批中"或"已驳回"时是否也允许管理 Celebration）。
- 挂载模块（报名信息、涂鸦展示）本身的操作权限（签到、上传作品、发布/隐藏等）分别引用 `registration-004-admin` §7、`submission-003-admin` §7，本文档不重复定义。
- 员工/外部人士只读浏览 Celebration 详情页；报名、涂鸦投票的具体权限分别引用 `registration-004-admin` §7、`submission-003-admin` §7。

## 8. 校验规则

- 创建/编辑时必填：所属活动、Site 名称、Celebration 标题、Category、开始时间、结束时间、封面图-预告版。选填：封面图-实拍版、文字描述、图片相册、Highlights。
- 结束时间必须晚于开始时间，独立于"是否为空"校验单独提示（与 `activity-001-admin` AC-002 的处理方式一致）。
- 挂载"报名信息"模块时：报名截止时间、名额上限为选填字段，具体校验规则引用 `registration-004-admin` §8。
- 挂载"涂鸦展示"模块时：投票截止时间必须晚于提交截止时间（原由 `module-002-admin` 承载的规则，随挂载对象变更迁移至此，规则内容不变）。
- 一个活动下可创建的 Celebration 数量不设上限。

## 9. 页面与状态清单

| 页面 | 需要的状态 |
|---|---|
| Celebrations 管理（创建/编辑表单 + 列表，按活动/状态筛选） | normal / loading / empty(该活动下从未创建过 Celebration) / empty(筛选无结果) |
| Celebration 详情页（用户端，含报名入口、图片相册、涂鸦展示） | normal(已举办) / normal(即将开始，相册与涂鸦展示为空态) / loading |

## 10. 验收标准

- AC-001：创建 Celebration 时，所属活动/Site 名称/Celebration 标题/Category/开始时间/结束时间/封面图-预告版为必填，缺失时对应字段高亮报错，阻止保存。
- AC-002：结束时间早于或等于开始时间时，即使其余字段均合法，保存时单独报错"结束时间需晚于开始时间"。
- AC-003：当前时间早于 Celebration 开始时间时，用户端详情页展示预告封面；开始时间已到达且已上传实拍封面时，页面自动切换展示实拍封面，无需人工操作。
- AC-004：一个活动下创建 Celebration 的数量不受限制，创建第 4、5……个时不出现任何数量提示或阻止。
- AC-005：同一活动下不同 Celebration 各自的报名人数、作品与投票数互相独立，某个 Celebration 的报名记录不出现在其他 Celebration 的名单里（与 `registration-004-admin` AC-004、`submission-003-admin` 联动验证）。
- AC-006：挂载"涂鸦展示"模块时，投票截止时间早于或等于提交截止时间，保存时报错阻止。
- AC-007：Celebration 的创建/编辑操作不产生任何审批记录，保存后立即生效，活动详情页/管理列表可立即查询到最新内容。
- AC-008：用户端 Celebration 详情页的报名入口仅对本 Celebration 生效；员工在活动下的多个 Celebration 中可分别报名，互不冲突、互不覆盖。

## 11. 已知缺口与非目标

| 缺口 | 谁来定 | 何时前定 |
|---|---|---|
| 封面图"实拍版"未上传但已过开始时间时，是继续展示预告版还是展示统一占位图 | 行政 | 开发排期前 |
| Celebration 是否需要"删除"能力，及删除的前置条件（是否要求先无报名/无作品记录） | 行政 | 开发排期前 |
| Category 的枚举取值范围是否需要收敛为受控列表（当前探索性原型草拟 Milestone / Team Building / Appreciation / Festive / Other，未最终确认） | 行政 | 开发排期前 |
| Highlights 是否需要成为结构化字段（如允许排序、图标），还是维持自由文本多行输入 | 行政 | 开发排期前 |
| 活动处于"审批中"或"已驳回"状态时，是否仍允许行政管理该活动下的 Celebration | 行政 | 开发排期前 |
| Celebration 详情页的图片相册是否有张数上限、是否需要排序能力 | 行政 | 开发排期前 |
